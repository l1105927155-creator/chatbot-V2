# 本群自动任务

用户提出“定期做某事”“到某时检查”“以后每天写日记”，或询问已有任务时，使用本能力。任务定义保存在本群 `automation/tasks.json`；AstrBot 负责按时触发。通过工具维护清单，读取工具返回的实际登记状态和执行记录。

## 创建和管理

先用 `task_list` 查看现有任务，避免为同一目的重复创建。根据用户要求确定任务内容、频率和时间；时间没有时区时使用 Asia/Shanghai，频率或时间不足以建立日程时简短确认。明确的请求直接办理。

用 `task_manage` 管理任务：action 为 create、update、enable、disable 或 delete。创建时传 definition，ID由宿主生成；修改时带 task_id、需要变更的定义字段及上次查询返回的 expected_revision。并发冲突时重新查询后核对，不覆盖他人的更新。工具成功、registered 为真且 scheduled 与下次触发时间符合要求后，再向用户确认任务名称、日程和下次触发时间；工具报错或未登记时如实说明。

助理任务 definition 使用：

```json
{
  "name": "定期日记",
  "kind": "agent",
  "enabled": true,
  "schedule": {
    "type": "cron",
    "expression": "0 23 * * *",
    "timezone": "Asia/Shanghai"
  },
  "prompt": "结合当前人格、可访问的本群经历和已有日记，写下今天的日记，保存到 diary/日期.md。区分经历与自己的感受，保留已有内容，不凭空补出缺失经历。保存后读回核对。",
  "parameters": {}
}
```

用户要求“同时发群”或“成功后汇报”时，把发送要求写入任务prompt；依据本群指南和用户要求选择文本或文件。文本使用 `qq_send_origin`，文档、长报告或指定附件使用 `qq_file_send`；只要求保存时，完成保存和核对即可。

上述每天23点只是结构示例，实际使用用户给定的时间。cron表达式依次为分、时、日、月、星期。固定间隔使用 `{"type":"interval","seconds":120,"start_at":"带时区的ISO起始时间"}`；一次性任务使用 `{"type":"once","run_at":"带时区的ISO时间"}`。建立日程后以返回的下次运行时间核对时区和频率。

任务属于当前群。群身份与请求来源由宿主绑定，创建/修改工具不接受自行指定的群号或执行身份。定时轮次沿用已登记来源的现有权限；没有工作区写权限时，不能承诺任务能够写入日记或其他文件。

## 定时执行

宿主会用独立任务轮次执行保存的 prompt，提供任务身份和执行时间；本群人格、工作区及Skill沿用当前配置。按任务内容执行并核对产物。按任务要求决定是否向本群发送消息，文本使用 `qq_send_origin`，文件使用 `qq_file_send`。文件沿用普通群聊的本群工作区范围及传输方式，已有报告可直接按路径发送。任务轮次的最终回答仅用于内部完成记录，不会自动发群；不要用最终回答代替已经要求的发送操作。静默任务完成内部工作即可。重复触发由已有日程管理。

日记保存到工作区 `diary/`。按实际日期选择文件，保留已有日记；使用可访问的历史、记忆和已有资料，不把缺少记录推断为没有发生，也不把模型猜想写成已经核实的经历。是否写入成功以实际文件检查为准。

## 查询与取消

用 `task_list` 查询本群清单、登记状态、下次触发和最近结果。助理任务的 `status=completed` 只表示轮次结束；同时查看 `result.outcome` 和 `result.summary`，如实说明 Agent 报告的成功、失败及原因。`unknown` 和没有结果的旧记录表示结果未确认，不得说任务成功。Agent 自报不等于宿主核验，需要时读取工作区文件检查。区分“已配置但未登记”“执行中”“条件不足跳过”和运行错误。暂停使用 disable，恢复使用 enable，取消使用 delete。失败不自动重试，后续周期是否执行以实际日程为准。

日常记忆整理由记忆插件的后台增量能力负责，按新增群友消息数或等待时长触发，在群聊记忆页配置。查询工作区任务清单时，以实际清单为准；无需为日常记忆整理另建定时任务。成员明确要求额外的定时记忆任务时，按其要求维护。
