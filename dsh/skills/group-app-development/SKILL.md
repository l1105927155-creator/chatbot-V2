# 开发本群应用

先加载 filesystem，检查本群已有应用、工作区指南和相关 Skill。将成员需求整理成可验证行为，保留已明确的机制；影响体验的新增玩法单列建议。成员要求先讨论时，先给简明方案，收到确认再修改文件。选择本群现有工具能完成的最小实现。

## 指南分工与按需读取

工作区 `/workspace/AGENTS.md` 负责本群工作约定与能力入口。新增应用时，在其中补一小段适用场景、触发条件和 Skill 名称，让完整应用规则留在应用目录。

每个应用维护自己的 `AGENTS.md`，封装该应用已确认的业务约定、资料入口及维护方法。`persona.md` 继续负责本群性格与表达，应用通过引用使用当前人格。

应用 Skill 的摘要帮助后续会话发现能力，正文负责使用流程：先读取应用 AGENTS，再按需读取配置和相关成员数据，执行操作并核对结果。当前运行时自动注入的是工作区根 AGENTS 与 persona；应用子目录的 AGENTS 需要通过本群 Shell 显式读取。读取应发生在相关应用的使用或维护任务中；后续修改后使用最新内容。

例如，工作区 AGENTS 的入口可以是：

> 与成员直接交流或处理好感查询时，加载 affinity Skill，按应用指南读取和维护本群关系记录。

对应 Skill 中写明：

> 先通过 Shell 读取 `/workspace/apps/affinity/AGENTS.md`，依其中的入口查询该成员记录，再调用应用；以实际执行和保存结果回答。

## 每类信息只维护一处

为每类信息指定权威来源，其它文件通过路径引用：

| 信息 | 权威来源 | 其它层怎样使用 |
| --- | --- | --- |
| 应用目的、业务定义、已确认机制 | 应用 AGENTS.md | Skill 读取，工作区 AGENTS 仅索引 |
| 用户需求中明确可配置的选项 | 应用配置文件（确有需要时建立） | 代码直接读取；应用 AGENTS 解释字段意义并指向配置 |
| 成员分值、变动依据等持久状态 | 应用的数据文件 | 查询和修改通过应用操作，以保存结果为准 |
| 群性格、表达偏好 | 工作区 persona.md | 应用指南引用当前人格 |
| 调用步骤、输入和成功检查 | 应用 Skill | 工作区入口指向该 Skill |

固定业务边界由应用 AGENTS 说明、程序执行并通过测试核对。只有成员需求明确包含可配置选项时，才将其集中到配置文件并由代码读取；调整时修改该配置并验证行为，入口指南保持引用。程序执行规则、测试验证规则，与在多份指南中手工维护同一套规则不同。

规则变更先更新对应权威来源，再检查调用步骤及测试是否需要随行为调整。发现已有多份规则不一致时，结合成员已确认要求核对后收敛，保留已有有效内容和可恢复副本。

## 轻量结构与交付

新应用可采用 `apps/<name>/AGENTS.md`，实现、配置、数据和聚焦测试按需放在同一应用目录；调用入口放在 `skills/<name>/SKILL.md`。维护已有应用时沿用合理结构。参考 skill-authoring 创建或更新入口，并在下一请求确认发现与正文读取。

按需求验证脚本和真实使用流程：首次直接互动、无状态变化、重复事件、成员改名、新会话读取及状态查询。测试使用隔离样例，核对工具结果和持久文件；涉及共享数据更新时验证重复处理、写入中断及恢复。数值约束由代码检查，是否在聊天中正确调用还需用实际模型对话验证。

交付时简述入口、实际测试和未通过项。新会话能够发现、读取并使用应用，是验收的一部分；一次自测通过仅证明其覆盖到的行为。

## 应用业务执行与编辑权限

用 `group_app(app, operation, args)` 调用面向所有成员开放的业务操作。这个入口按原生工具参数传字符串数组，固定执行应用自己的Python程序；不传Shell命令、解释器、工作目录或环境变量。工作区代码与指南只读，仅本应用 `data/` 可写，普通成员聊天也可以由Bot判断并维护应用数据。

应用在 `apps/<name>/app.json` 声明入口和开放操作，例如：

```json
{"version":1,"entrypoint":"affinity.py","operations":["get","list","ensure","record","name"]}
```

应用名使用字母、数字、下划线或连字符；Python入口是本应用目录内的非隐藏文件名。数据目录固定为 `data/`，不声明任意写入路径。开发者初始化该目录并验证应用在“代码只读、数据可写”的环境中运行。

清单、代码和规则的修改使用原有白名单编辑通道，不通过业务入口修改。仅列出日常业务需要的操作；重置、删除档案等管理操作留给有权限的管理通道。好感幅度、互动判断等业务规则由本应用代码和AGENTS维护，不在多处复制。更新应用Skill，把日常操作改为group_app调用；读取应用指南仍可用只读Shell。

自检使用临时测试数据，避免修改真实记录。需要多步检查或开发时，通过background-research委派并尽快结束前台轮次；后台沿用发起任务者权限，应用数据入口不授予通用代码编辑能力。
