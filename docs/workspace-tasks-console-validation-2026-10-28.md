# 自动任务控制台与正式启用机制

用户要求：自动任务纳入V2 Bot控制台；生产运营能力完整后，通过开关试点，不能以临时环境变量群名单代替正式接入。

## 实现

- 控制台增加“自动任务”页签。列出所有已准入群，管理统一默认和单群覆盖，支持创建、编辑、启停、删除、立即执行、取消，以及下次执行时间、最近10次状态和错误。编辑绑定原群与原revision；停用任务编辑不会重新启用，冲突要求重新核对。
- 策略持久保存在任务插件SQLite中，版本CAS更新，热生效。旧试点名单仅一次性迁移，新群自动发现并继承统一默认，无需改环境或重启。Skill原本已通过全局provider对所有群可发现，不需要逐群复制。
- 群开关关闭后撤销调度、取消并排空运行，保留清单和日程。已接管群的记忆任务随群开关暂停，旧入口不会回退或双跑。尚未接管群保留原有记忆配置；原legacy runner的首次名单冻结行为保持，新群需启用工作区任务管理才会登记每日记忆任务。
- Bot和页面共用manager与群任务文件。网页Owner身份由现有控制台认证，宿主绑定对应配置中的QQ Owner；执行前验证当前群准入、策略、定义hash、来源登记与Owner，普通群消息任务继续使用真实Journal来源。Dashboard任务不伪造QQ入站消息。
- 手动执行使用持久请求幂等和稳定run_id，与原定日程分别记录。定时和手动运行均可取消；关闭、删除、改任务、排队取消、首次callback前取消、请求中途取消都会收尾持久状态。重启标记中断，不重放旧运行。手动执行一次性任务不消耗原定触发。
- 调度保留AstrBot原生APScheduler。撤掉独立任务页与只读状态API，统一从控制台进入；不改上游core。

主要文件：`v2_tasks/main.py`、`workspace_manager.py`、`workspace_store.py`；`v2_console/controller.py`、`runtime.py`、`main.py`、页面源码及构建产物；Router只补充`run_scheduled`对Dashboard可信登记来源的核实。
