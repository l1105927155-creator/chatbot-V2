# QQ 分段回复诊断

## 结论

用户引用的实际回复有 **198 个字符、3 个自然段**，各段长度为 103、49、42。当前发送器对 **600 字符以内**的最终回复直接整条发送，因此这条回复不会拆成 2–3 条。换行是文本结构，不是 QQ 消息边界。

这不是指南未加载：生产原生 Session 记录确认，相关 Profile 和共享指南在该问题及答案之前已进入系统消息。现行 Profile 和 `qq_send_origin` 工具说明又要求最终回答交给自动发送；程序只对长文分组，两者形成了“模型组织段落，程序决定消息数”的现行策略。该策略不能满足用户此次提出的“约200字、多个完整意思也适合分条”的期望。

真实 Flash 有分别发送的能力，但自主分条的软指南在本轮样本里也没有达到目标：现行指南、只改 Profile、同时改 Profile 和工具说明的三种条件下，自然问题都仍得到单条回复；明确要求使用工具发送第一条、final 发送第二条时能做到。因此不能把问题全部归因于模型理解能力不足，也不能仅凭指南加载成功就宣称行为生效。

## 原因与建议

1. **程序是原案的直接原因。** 198字符的 final 无论模型如何认真换行，都不会进入自动分组分支。不是 QQ 客户端把多条消息合并，也不是换行丢失。
2. **现行指南描述的是较窄的策略。** 它支持长文组织和自动发送，没有要求这类中短回复成为多条 QQ 消息；工具说明还把 final 正文留给自动发送。不能将遵循现行策略的单条输出一概判断为模型不服从。
3. **软指南本身也不提供稳定保证。** 沙箱两种改写均已实际加载，但自然问题仍未触发工具分条；明确消息边界控制成功只证明能力存在，不能证明模型能稳定自主选择边界。上下文溢出、热更新失效和缺乏发送能力没有得到证据支持，不需要把它们当作原案主因。

建议将“文本自然段”与“QQ消息边界”分别定义：单一意思简短发完，多个可独立阅读的意思允许成为2–3条消息；600字符只作为长文阅读保护，不能作为唯一触发条件。要稳定实现用户对本例的期望，需要对齐发送契约及程序支持，并以原文是否实际收到2–3条作为验收；仅增加“请分段”的提示强度不足。也不建议把所有空行机械地变成消息，会把短引言、列表和代码拆碎。

本轮是诊断，**未修改正式指南、发送策略或服务配置，未重启正式服务**。只新增本文及忽略目录下的实验材料；正式服务与部署源文件摘要在结束时复核。
