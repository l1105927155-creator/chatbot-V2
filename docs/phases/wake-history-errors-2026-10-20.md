# 唤醒历史与故障回复（2026-10-20）

状态：已完成实现、完整工程门与5个完整模拟 QQ 场景验证，并备份部署。生产服务与 QQ 连接健康；已核实的旧模型失败轮次精确解除暂停，无重跑、无 Session/模型/工作区重置。见[验证与部署](../wake-history-errors-validation-2026-10-20.md)。

## 目标与边界

1. 当前请求附图、明确引用消息中的图片自动作为视觉输入；其余历史图片保留 canonical Journal 关联，按需通过图片读取工具查看。引用与读取受当前会话、重置点和本轮上界约束。不自动生成图片摘要，不将临时视觉缓存视为工作区文件保存。
2. 旧轮次的视觉块在下一轮模型请求前卸载成原生附件引用，保留文本、原始附件和本轮工具后续请求的视觉能力。使用固定 DSH 的原生投影扩展，不修改上游 core。
3. 工具业务失败返回模型处理；确证请求已终止且没有未知执行结果的模型失败，由程序简报并结束失败轮次；基础设施故障由程序简报并挂起受影响 Agent 会话；执行结果未知时保留暂停并给出具体核对与恢复路径。错误文本使用受控原因，不透传堆栈、密钥、请求正文。
4. 状态与恢复命令、独立 AstrBot 插件不依赖模型生成回复。基础设施整体停止时无法承诺立即通过 QQ 通知，沿用 systemd 与健康检查恢复，不新增独立聊天链路或外部告警平台。
5. 恢复不自动重跑有副作用的动作；模型、工作区、长期记忆与指南不因失败被静默替换或删除。明确上下文错误优先修复视觉投影，再提供 /new 的明确入口。

## 实现位置

- Router：vision.py、mcp_server.py、service.py、dsh_client.py、state.py、turn_error.py、main.py：图片选择/读取、结构化运行证据、持久故障状态及确定性回复与恢复。
- DSH 扩展与 Profile：原生历史图片卸载、终态证据、图片读取工具白名单；chat-history Skill 说明按需查看。
- 对应 Python/Node/固定 ACP 测试、运维文档与本阶段验证记录。

## 验收证据

- 历史多图+文本唤醒不发送历史像素；当前图与引用图能看见；历史按需工具返回真实图像；越界、跨群和 /new 前读取失败关闭。
- 同一原生 SID 下一轮旧图卸载、当前轮工具后续请求保留视觉；恢复 SID 后仍生效；文本与 Journal 保留。
- 模型拒绝、工具业务错误、运行时断连、工具执行中断/未知结果、发送失败分别注入；核对程序回复、pending/cursor、重启后故障与恢复、无重复执行。
- 不回归 Owner/群/safe-chat 执行域、后台任务与模型目录、确定性命令、现有指南热更新。
- 使用隔离模拟 QQ 与固定 ACP；部署仅应用本任务差异，保留工作区未发布的交流表达修改。真实 QQ 收件与长期反馈如未现场验证则明确列出。

## 依据

原生 DSH image/offload 消息投影保留附件，适合视觉生命周期管理；ACP 的模型/终态与工具事件用于判断已完成/未确认，传输丢失不能仅凭未收到工具通知推断没有执行。OpenClaw 的终态通知/有限恢复、systemd 的进程恢复是参考，不引入其整套平台。现有 WB 图片诊断见 ../vision-wb-diagnosis-2026-10-20.md。
