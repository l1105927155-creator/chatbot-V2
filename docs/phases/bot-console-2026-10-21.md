# V2 统一控制台：需求、适配与验收

日期：2026-10-21。状态：已实现、验证并部署；真实客户端体验待用户验收。进展与证据见[验证记录](../bot-console-validation-2026-10-21.md)。

本文件记录用户逐项确认的产品规则，作为实现边界。历史文档中的群成员共享修改、普通非 Owner 私聊 safe-chat 等是已部署行为，不代表新控制台目标；当前生产行为以本阶段验证和部署记录为准。

## 1. 入口与职责

- 主入口采用 AstrBot 插件自定义页面和管理 API，复用 Dashboard 身份验证；控制台管理操作仅供 Bot 总 Owner 使用，不能把任意已登录 Dashboard 身份等同于 Bot Owner。
- 后续用户已确认只有本人使用 AstrBot 管理员账号，并授权该账号管理控制台。实现匹配当前配置的 Dashboard 管理员用户名，拒绝其它登录身份/API key 伪用户；不从 QQ 昵称推断后台身份。
- AstrBot 负责平台放行、确定性插件、收发与 canonical Journal；Router 负责会话调度、串行、游标与恢复；DSH 保持认知主体，权限由程序执行。
- DSH Web 保留模型目录与凭据管理，Bot 复用现有共享目录；不复制模型管理系统，不合并 Web 与 QQ 的 Session、home 或权限。
- Bot 服务由 `chatbot-v2-agent.service` 管理。不增加通用控制平台，不修改固定版 AstrBot/DSH core，不改变正常 QQ 收发路径。

## 2. 默认设置与工作区模板

基本设置只有一套可编辑的「默认设置」。新会话创建时复制当时的值并独立保存，不持续继承。修改默认设置只影响之后创建的会话。

会话设置每个字段提供「恢复默认」，将当前最新默认值填入该字段，随会话设置保存；不是恢复创建时快照，也不建立继承。默认设置自身没有恢复默认。

workspace 可自定义多套模板，包含目录结构、`AGENTS.md`、`persona.md`、Skill、群应用代码及初始配置。创建工作区时复制，后续模板编辑不覆盖已有工作区。模板不携带来源群的成员数据、变动历史、凭据或备份；模板内容不授予权限。既有会话不得因为选择模板而被清空或自动覆盖。

工作区是该会话持续保留的背景与能力集合。切换模型、禁用/启用、重启、压缩、`/new`、`/reset` 均保留工作区。本阶段不设计拆除、删除或重建工作区的功能；编辑器的单文件删除是用户主动文件操作，不能作为会话重置副作用。

## 3. 接入与身份

- 私聊仅开放给配置的 Bot 总 Owner，不给其他私聊创建 Agent Session 或工作区。Owner 私聊保持现有主机执行域，不额外分配群式持久卷。
- 用户只在控制台添加群一次，选定 workspace 模板并复制默认设置。服务端联动 AstrBot 平台会话白名单、V2 Agent 准入及工作区初始化，保留原配置。
- 自动同步指用户确认添加后的配置联动。Bot 加入群不自动授权 Agent，也不自动分配工作区；自动发现待接入群不属于本阶段必需功能。
- 多步骤失败须报告实际完成情况与重试路径，不能虚报成功，不能回滚删除已有群数据；并发新增仍服从现有卷预算和磁盘余量检查。
- 身份使用 platform/bot/conversation 完整标识，界面显示群名（取得时）和群号；不靠群名或长哈希让用户辨认。

## 4. 权限与群应用

平台会话白名单、Agent 准入和工作区修改白名单是三个不同概念。

| 主体 | 允许范围 |
| --- | --- |
| Bot 总 Owner | 控制台、默认设置、各会话设置、成员白名单、模型、服务重启及现有 Owner 能力 |
| 当前群修改白名单成员 | 普通成员能力，加当前群工作区创建、修改、删除；不获得控制台管理、模型切换、其他群或宿主权限 |
| 普通群成员 | 聊天、读取允许的资料、查询应用，以及应用明确开放的业务操作 |

成员白名单仅由总 Owner 在后台维护，保存于工作区外的可信状态中。工作区内 `Owner.json` 不再作为程序鉴权来源，不能通过改文件增加权限。迁移前须盘点其实际使用者，不把应用内部业务角色与程序权限混为一谈，不直接复制旧文件为可信名单。

普通成员默认不能写工作区。群应用可明确开放签到、投票、修改本人资料等具体操作，由程序检查请求者和数据范围；开放某业务写入不等于开放数据库文件、任意路径或其他成员记录修改。未开放的写入拒绝。

后续已确认：所有成员保留向专用附件目录收件的能力，由程序生成位置且不得覆盖任意工作区文件；这是明确的收件例外，不授予通用写权限。控制台阶段先完成权限边界；后续[应用操作与单步超时](group-app-operations-step-timeouts-2026-10-22.md)已为好感应用提供独立数据写入通道，其它未适配写操作继续拒绝。

所有入口落实同一边界，包括文件工具、Shell、应用调用和派生/后台执行。不得仅提示模型拒绝或只检查 Shell 文本中的命令名称。若现有执行入口不能可靠实现普通成员只读，须限制该入口并保留明确的查询能力，不能静默放开工作区写入。

## 5. 模型

- 默认模型从现有共享模型目录选择；会话创建时复制，之后独立保存。
- 仅总 Owner 可以修改默认或会话模型，包括 `/provider` 切换；其他成员可查看当前模型和目录。
- 会话「恢复默认」和 `/provider default` 应采用当前默认值并独立保存，不能继续隐式跟随部署默认。
- 切换保留历史、SID、工作区；当前轮继续原模型，后续轮应用新模型。删除或不可用的模型明确报错，不静默替换。

## 6. 禁用与重新启用

- 禁用仅停止该会话 Agent 新输入与唤醒；Journal、AstrBot 确定性命令及订阅推送保持运行。
- 禁用取消当前轮及后台研究，并阻止排队输入、迟到结果或完成通知在禁用后继续作为 Agent 输出。已经发生的副作用不撤销；不确定结果仍保留 pending/待核对，不能靠禁用或重启清除。
- 启用不调用模型，不补执行旧请求。首次新唤醒保留禁用前上下文，补入禁用期间近期原文作为背景，明确历史间隔；较早消息按需查询。
- 恢复范围由程序统一管理，不新增控制台设置（用户已确认）。当前保留最多100条、32KiB UTF-8输入上限，以隔离回放验证裁剪与边界，再按实际模型 usage 持续校准；固定版原生 token 计量为启发式估算，不把字节上限冒充精确 token 预算。该上限仅针对本次补入的 Journal 输入，不清除禁用前的原生上下文。游标推进与背景输入必须区分，不能造成遗漏新消息或重放禁用期间指令。已有 `/new` 历史可见边界保持。

## 7. 后续上下文工程的常驻业务原则

压缩、保留近期原文和按需检索结合使用。压缩造成的信息损失必须验证，不能仅以 token 减少为有效证据。该原则适用于之后所有上下文工程变更。

- 保留 DSH 原生自动压缩；现配置 `thresholdRatio: 0.8` 是已有值，不是已验证的质量最佳点。降低阈值前比较实际群聊样本。
- 控制台提供手动「立即压缩」与「新建对话上下文」，两者均保留工作区和 Journal，并尊重现有上下文重置隔离规则。
- 不默认自动「总结后 /new」，不由模型自行清空会话。带交接摘要的新对话不属于本阶段默认功能；若后续提供须可查看、编辑摘要。
- 指南每次请求加载最新有效内容；历史、摘要、当前请求区分来源，摘要不是权限依据。加载成功不能视为模型遵循成功。
- 评估覆盖关键决定、撤销与纠正、未完成任务、来源与不确定性、旧指令误执行和指南遵循，保留失败样本；无证据不宣称解决判断衰退。

## 8. 编辑器与远程访问

控制台提供会话文件树及内置代码编辑器，支持目录浏览、文本/代码编辑、新建、重命名、删除、上传和下载。保存发生于 197 Linux 服务端；Windows 等远程浏览器无需挂载 Linux 文件系统。浏览器本地文件选择器仅用于上传。

- 群仅显示对应已验证工作区；Owner 私聊仅显示配置的 Owner 工作目录，不提供整个主机浏览。
- 服务端验证会话身份、路径与真实文件对象；过滤文件树不能代替阻止路径穿越、链接越界和跨群访问。
- 打开后文件被 Bot 或其他页面修改，保存时报告版本冲突，不能静默覆盖。文本保存、上传和重命名处理失败保持可核对状态。
- 指南/人格按现有热加载生效；代码保存不等同于应用已重载，界面如实显示生效方式。
- 当前 AstrBot 配置监听 `127.0.0.1:6186`。局域网使用需配置监听、反向代理或 SSH 转发之一；实现时核对实际部署连接和 Dashboard 鉴权，不因支持远程编辑而开放匿名文件接口。
- 默认设置和可信权限存储不是可编辑的会话文件，群 Agent 无法通过模板、链接或应用读写获得控制台权限。

## 9. 重启

主操作为重启 `chatbot-v2-agent.service`，不是调用 AstrBot 自身进程重启。先停止新 Agent 输入并取消当前任务，保留工作区、Session、Journal、模型选择、cursor 和 pending；不自动重放。独立 DSH Web 不随之重启。

重启请求交给 systemd 后应能跨 AstrBot 进程退出继续完成，不能让发起重启的处理任务随目标 cgroup 一起被终止而造成半途停止。只允许固定服务操作，不暴露任意 unit 或 shell 参数。重连后核对新进程、核心健康及 QQ 就绪，不能把 HTTP 重新可达当作重启成功。

Bot 停机时插件控制台也不可用；本阶段不增加独立常驻停机启动控制台。

## 11. 实施顺序与预期文件

1. **管理状态与迁移**：新增小型可信配置模块及管理插件（拟 `astrbot-plugins/v2_console/`），保存一套默认设置、多模板元数据、按会话设置快照和群修改白名单；原子保存、版本冲突检查。盘点已有会话与应用 `Owner.json` 使用，不覆盖旧工作区，不自动赋权。
2. **先落实服务端权限**：调整 `dsh/plugins/agent-profile/` 现有执行边界及应用入口，绑定可信当前请求者和最新名单；覆盖后台/派生执行。同步相关指南，禁止仅做前端限制。
3. **会话管理**：适配 Router `main.py`、`service.py`、`state.py`、模型模块与 `scripts/agent-service.py`；完成一次添加、Owner 私聊限制、设置快照、启停、近期背景和模型更新。跨组件保存明确失败恢复，不引入额外 ledger。
4. **工作区与模板**：扩展 `group_volume.py` 及现有文件校验组件；新增会话限定文件服务。测试目录、链接、冲突与容量后接入编辑器。
5. **页面与运维操作**：管理插件提供设置页、会话列表、模板与 Monaco 编辑器；接入固定 unit 的异步重启、重连健康状态与原生手动压缩。静态页面单独打包，不假设可直接导入宿主前端内部组件。
6. **完整验证与部署**：新增聚焦 Python/原生 Node 测试和隔离模拟 QQ 场景；受控备份后发布，验证实际远程浏览器与真实 QQ。更新运维手册与验证记录，区分自动验证和真实体验验收。

具体模块划分在实现时按原生接口验证收敛，不创建新的通用权限/运行平台。本阶段实现已按后续执行授权完成备份与受控服务重启；没有扩大网络监听范围。

## 12. 验收清单

- 默认值变更不改变已有会话；字段恢复默认取最新值；模型命令与后台一致，重启后保持。
- 多模板初始化结构完整、只复制初始数据；既有文件、工作区、SID、cursor、pending 与 Journal 不被覆盖。
- 添加一次即同步两层准入；配置写入失败、并发、磁盘不足及中途停止均可核对恢复；未接入群不响应，其他私聊不建 Session。
- 普通成员可以聊天/读取/查询但不能从文件、Shell、应用或子任务任一入口任意写；群白名单只写本群；改 `Owner.json` 不提权；名单撤销后后续操作使用最新状态。
- 应用开放写入仅命中指定业务与数据范围，不能变成任意脚本或 SQL 执行；现有应用逐个验证，未适配写操作拒绝。
- 禁用与入站、工具执行、后台完成并发时屏障有效；保留平台功能与 Journal；启用不调用模型、不重放旧指令、不漏新输入、不绕过 `/new` 边界。
- 文件接口拒绝跨群/越界/链接绕过；并发编辑报告冲突；Windows 浏览器可编辑 Linux 正确工作区；未授权请求被拒绝。
- 服务重启实际重新经过配置加载器；任务取消、迟到输出隔离、pending、工作区和会话持久性正确；独立 DSH Web 不受影响；失败不显示成功。
- 原生自动/手动压缩可用；压缩前后比较关键事实、纠正、未完成任务及指南遵循，保留信息损失与失败证据；不以 token 减少或指南加载当作业务通过。

验收按实际实现逐项执行，源码、模拟平台、真实模型与生产部署分别记录，不以本清单本身作为通过证据。
