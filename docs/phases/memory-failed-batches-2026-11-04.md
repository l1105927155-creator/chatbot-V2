# 失败批次跳过与插件页手动重整

用户要求：失败轮次保存原因并跳过，继续整理后续消息；仅由 Owner 在后台插件页触发历史失败批次的重新整理。此条取代此前“任一失败范围暂停整个群增量”的运行合同，不追加自动纠错或反复模型重试。

实现复用群卷 SQLite 的 runs 表，追加跳过范围、重整进度、状态与诊断字段。失败仍记为 failed；扫描游标前进只代表该范围已写入或已明确跳过，不将失败冒充成功。后台处理与跳过共用原有整理锁；保存诊断及推进游标为同一事务。旧失败/中断记录最多跳过其当前100条Journal页，有明确模型批次范围时采用更小上界，未尝试余量继续正常处理。用户取消保留手动恢复入口。

插件页分页列出失败范围、原始错误类别、模型、时间、当前重整进度及诊断。现有安全诊断包括阶段、验证错误、异常类型/代码、引用定位、受限模型输出片段和来源上下文；第三方密钥与原始供应商异常不输出。历史上没有保存的明细明确显示缺失，不根据泛化错误码编造原因。跳过记录中的诊断不受原临时诊断表最近32条清理影响。

手动重整通过原有后台worker异步执行，同群串行。读取原Journal、当前人格/聊天模型和当前记忆，经完整来源/事实验证；提示保留后来信息。提交时使用当前记忆revision CAS，在同一事务写入记忆和更新重整子批进度，始终保留主线扫描游标。部分成功后从未提交子批继续；整段成功后按钮不再可用。失败保留原记录与最近一次重整诊断，不自动重跑，也不暂停正常后台整理。业务事实的语义准确性仍受模型能力限制。
