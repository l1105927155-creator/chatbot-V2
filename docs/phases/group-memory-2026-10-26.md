# 群聊记忆最小闭环

状态：最小闭环已实现，工程回归、scripted 端到端和真实模型小样本通过；2026-10-27已接入生产当前7个准入群，见[生产接入记录](../group-memory-deployment-2026-10-27.md)。

## 目标及边界

以当前群 Journal、当前有效 Persona 和必要既有记忆，形成 Bot 对群内经历的连续理解。每群一库，跨 Session、跨 Persona 保留；不使用 confidence 或可靠性准入，不常驻注入记忆，不线上导入启用前历史。

已完成前置包括 canonical Journal、核验群卷、受限 MCP、群 `/new` 整理接入口及每日 22 点/99 条群友消息的自动任务。用户补充确认：允许按当前群真实记忆 ID 定点核实 `/new` 以前的关联消息。宿主校验来源并限制条数，普通历史查询继续遵守重置下界，不开放宿主文件或任意旧历史搜索。

采用薄自研存储及集成。旧插件的 confidence、原始消息库、成员档案和旧 Session 模型与本轮不符，整包迁移成本更高；选择性参考其检索与页面思路，不复制旧架构。后台模型复用固定 DSH 的原生 `llm.stream`，不创建认知 Session、不提供工具，不新增模型凭据或发送通道。

## 修改计划

- `astrbot-plugins/v2_memory/`：群卷内 SQLite 存储、修订与权威成功游标同事务；整理服务、来源验证、检索和 AstrBot 插件页。初始登记只保存群身份，不在宿主存第二份记忆内容。
- `astrbot-plugins/v2_journal/journal.py`：完整群身份绑定的有限区间和 ID 查询。
- `astrbot-plugins/v2_dsh_router/mcp_server.py`：按需记忆检索和按记忆 ID 核实来源；服务挂接自动任务与 `/new`。
- `dsh/plugins/agent-profile/memory-consolidation.mjs`、群 profile 及 `dsh_client.py`：私有宿主 socket 接入一次性无工具模型请求，复用群当前模型与人格，支持取消和真实用量。
- 沙箱快照、中文记忆职责说明和分层测试。

记忆权重仅表达长期显著性，不表示真实性。模型结合新来源决定合并、修订、归档与遗忘；不按一周未提及机械删除，不把检索次数算作证据。第三人反驳保留归属，不能静默改成当事人自身变化。媒体仅采用当前真实已识别材料，未识别部分只保留元数据。

## 实际交付

群卷内 `.v2-memory/state.sqlite3` 保存记忆、修订、来源、权威成功游标与无原文的运行记录；插件数据目录只保存首批群身份清单，已加入停写备份组件。每次存取先取得现有工作区短锁并核验挂载，不缓存可脱离群卷继续服务的连接。Owner 和已获授权的工作区编辑者仍可直接调试文件，这不是防止同 UID Owner 改库的机制。

每批最多100条 Journal，模型输入最多256KB；超限、格式错误、来源伪造、取消或版本冲突均失败，不静默截断后推进游标。各批记忆变更与游标一致提交；第二批失败时保留第一批已提交进度，但 `/new` 不因此清空旧会话，也不自动重试。模型等待期间不持 SQLite 事务或文件独占锁；返回后重新检查准入、采集健康、人格、模型及数据库 revision。

`memory_search` 单次完成精确和中文二元字符近似匹配，可按成员及记忆更新时间筛选，不调用模型、不自动循环查询。`memory_sources` 只接受当前群真实记忆 ID，每页最多20条，可按返回的 offset 继续定点核实。累计来源不设200条总上限；进入模型或前台检索结果的来源索引只显示首尾各20条及总数，全部引用仍在库内并可分页核实。没有引入向量库、独立 Agent 或任意旧历史查询。

管理页支持浏览、搜索、来源标记、修订、手动编辑、启停、导出、清理和运行/用量查看。CAS 冲突返回409，提示刷新核对。清理不回退游标；缺测用量为 null，失败或取消不把不完整消耗冒充总用量。意外退出留下的 running 记录在重启后变为 interrupted，不重放。Router 在关闭模型客户端及卸载卷之前先排空记忆服务，避免依赖插件卸载顺序。
