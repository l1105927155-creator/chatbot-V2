## 已观察事实与尚未成立的结论

- 原生 guard 能在直接执行前拒绝；restrict 仅限制全局工具，不能涵盖 Agent 本地与 MCP 注册。
- 本机原生 sandbox 支持工作区写入与 shell 删除；读取不受该 sandbox 的文件范围限制。
- 解析 persona 得到路径后替换为 symlink，实际原生 reader 会读取别的文件。复现发生在 provider 操作序列，尚未证明一个真实 QQ 请求者能利用此竞态。
- Linux 的文件句柄加 `/proc/self/fd` 委托可固定原生 reader 读取对象；仅验证 readText，没有证明 write/edit、stream、资源鉴权或跨平台全链路。
- 原生 overwrite 会读取旧内容并返回 before；write-only 权限不能自动授权这个读取副作用。
- 原生公开 FS 接口是路径型 target，没有固定文件/父目录句柄提交接口。单加工具执行前的 realpath 检查不能证明抵御检查后路径替换。

## 请评审员明确的决定

### 1. 精确资源边界的威胁模型

是否必须防御授权检查至实际 I/O 之间，外部进程或并发 owner 操作主动替换文件/祖先目录的竞态？

普通成员提交相对路径、`..`、静态 symlink 或通过间接工具绕过范围，已经由需求明确要求阻止；此处只询问额外的并发路径替换边界。上述复现说明潜在缺口，不应自动把它解释成已确认的攻击者能力，也不应自动放宽需求。

### 2. 如要求对象级保证，允许的最小修改面

候选方向：保留原生模型工具、sandbox 与版本/原子发布语义，在原生 FS provider 执行层绑定实际对象并进行部署授权检查；V2 仅提供可信请求者和最新名单。

请确定应采用哪种边界：

- 原生 provider 扩展/装饰，在公开接口内委托原执行；需实测证明 write/edit 等仍满足对象绑定，不能仅凭 read 候选成功接受。
- 若公开接口不足，允许提出固定上游的最小 FS seam 补丁方案，单独记录为何 plugin/configuration 不足、补丁面、回归验证与移除条件；不直接复制整个执行器。
- 其它明确的实现边界或威胁模型调整，请写出对授权规则和验收的影响。

现有探测没有证明第一种路径可完整满足写入/编辑；此次提交也没有实施第二种路径。不能在反馈前默认重做 V2 文件 MCP 工具或通用权限平台。

### 3. 原生操作的附带文件访问

建议按实际效果分别检查：overwrite 读取旧内容需要 read，edit 需要 read + write；仅有 write 且原生执行不能避免旧内容读取时直接拒绝。缺失父目录不从具体文件权限推出 mkdir 权限。

请确认这个处理是否符合产品预期，或是否需要另行要求原生 provider 提供不读取旧内容的覆盖模式。没有目录或通配授权的需求，不应自行添加。

### 4. 可信来源接入与生命周期

固定 ACP 没有已验证的 host 来源 metadata 接入或额外 host RPC 注册接口。最小候选为工作区外的私有运行期来源文件：独立 runtime epoch、精确 session、真实 requester、turn nonce；原生插件绑定实际 turn，操作前取得可信身份，结束收敛后清除。来源缺失或不匹配拒绝。

请评审这种事实传递是否接受，或指定更合适的固定版本原生接入口。它不保存授权决定；每次实际操作仍读取最新持久名单。后台/派生入口不得仅凭 session 自动继承来源，未验证入口不能默认为可用。
