# 四项审查整改（2026-10-17）

用户明确授权处理审查指出的四项问题并通过测试。执行域、可信身份、canonical Journal、pending/exact recover 和固定上游保持。

## 实施范围

1. Journal 采集异常先置运行期粘性故障，再尽力保存失败计数/时间/类别；健康区分数据库可读、采集器绑定正常、历史采集完整性。成功的后续写入不能抹除已知缺口。不伪造历史、不自动补写或重放。核对后才允许运维显式清除记录。
2. 模型/执行失败、取消确认、pending 暂停使用 AstrBot 提交简短状态提示；不转发异常正文。通知只尝试一次；同运行周期、同会话同 pending 的暂停提示仅一次，新的 pending 可以再次提示。不影响原有恢复权限和旧操作不重放语义。
3. 默认简短回答，完整长文按主题/自然段组织。现有最终发送路径对超过600字符且存在合适边界的文本做无损分组，目标300–500字符但允许完整语义单元更长；不硬切、不截断、不添加发送条数硬配额。短答、没有安全边界的长段及含代码围栏的回复原样交付。每段均经 AstrBot；任一段失败停止后续发送，按已有最终发送失败规则结束轮次，不重试。模型无需调用 qq_send_origin 搬运同一长答；该工具保留等候说明及独立工作流。
4. README、架构入口和 Personal Agent 阶段文档明确当前三组合/两信任域及逐群运行时。旧阶段记录标为历史，真实 QQ 固定故事及三天观察仍未完成。

第3项替代此前仅依赖模型调用 qq_send_origin 的分段实现：真实模型已看到指南却未执行，当前用户授权解决该项后，在既有发送路径添加小型确定性兜底。它仅分组原文，不进行二次模型重写或内容裁剪。简洁度仍需真实模型样本验证。

## 验收

- 聚焦测试检查 Journal 漏记、持久状态/运行期故障、绑定和健康接口；通知失败不递归、未准入无通知；分段无损及第二段失败停止发送。
- `scripts/check-review-remediation.py` 启动独立 scripted 沙箱，验证真实 AstrBot/DSH 链路中的分段、模型错误、pending 提示、exact recover 与故障注入后的健康状态。
- `--live` 使用继承的凭据及显式固定 provider/model，在独立模拟 QQ 测试问候、泛建议、新闻和完整 Git 七主题。先固定普通答案去 URL 后不超过300字符的弹性样本标准；长答超过600字符且有主题边界应分段。该标准只用于本轮样本，不是线上字数裁剪规则。
- 保存每轮失败/成功证据、源码指纹、消息/Journal/Router/原生调用关联；不把链路成功当表达通过。
