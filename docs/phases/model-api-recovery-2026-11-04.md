# 模型 API 故障转移与提示

用户最终指定备用为同一 `wb` 渠道的 `space-bunny`、`step-5-preview`，撤销 GLM。记忆整理逐次读取本群聊天模型设置。API 故障仅在失败的模型步骤内切换，每条不同线路最多一次；成功的工具不会重放，下一轮重新使用持久主模型设置。鉴权、输入、容量、输出长度和取消不作为可切换的接口故障。

## 写入与主线边界

严格校验协议格式、引用身份及原文、客观断言的可验证来源，再整批原子提交。事实复审仍有模型能力上限；引句有效不等于摘要事实正确，不承诺消灭模型误解。

格式或内容失败时拒绝当前候选、不做纠错重试、不用备用模型反复考试。保留原消息、失败诊断和未完成批次游标；已提交批次保留。后台暂停该失败范围，普通聊天继续。以后有具体修复或新证据时再显式回归；不自动循环重跑，也不把未整理消息假记为已完成。需要重置会话时沿用 `/new skip_mem` 的显式跳过选项。

## 实现与验证

复用固定版本 DSH 的 `agent/request`、`agent/request-error`、原生 compaction 扩展点。聊天、后台子 Agent、原生上下文摘要和无 Session 的记忆调用共用路由策略与安全故障摘要。保留 nonce 终态回执、工具完成证明、完整输入容量检查及 AstrBot 出站路径；错误提示不暴露供应商正文。故障转移跨请求的用量不完整时记为未知。

涉及 `dsh/plugins/agent-profile/model-recovery*.mjs`、三个 Profile、`turn-lifecycle.mjs`、`memory-consolidation.mjs`、`background-research.mjs`；宿主涉及 `model_failure.py`、`dsh_client.py`、`turn_source.py`、`service.py`、后台回调、命令提示和记忆后端/增量通知。故障转移使用插件接口；下述恢复兼容问题另有一个已记录、可重现的 ACP core 小补丁。

274项相关 Python/原生 ACP 检查通过；另有原生策略、compaction、记忆控制通道检查。覆盖两备用依次成功/全部失败、每条线路只请求一次、已有工具不重放、丢弃失败的半段流输出、取消、错误回执、下一轮恢复主模型、旧 Profile 兼容以及写入校验失败保留数据。均使用受控模型，不新增付费模型试验。

## 运行故障取证与恢复

11:45 的 `session/resume` 表面错误为 `Internal error`。复制失败会话、不发起生成后，原生 JSON-RPC `data.details` 明确为：`pi-ai provider "wb" has no configured model "deepseek-v4.1-flash"`。共享目录已改为 DeepSeek-V4-Flash、space-bunny、step-5-preview，但默认配置、控制台和原生会话仍保存已删除的选择；这一次错误发生在模型请求之前，不能归因于 API 临时故障。

另外，旧发布 Profile 通过目录符号链接加载正在修改的源码，形成版本不一致；未完成的事实检查模块撤回后仍有源码引用残留。已撤回额外事实检查/纠错循环，恢复可导入的记忆后端；生命周期对旧 Profile 保持兼容。新发布将可执行插件和 Profile 一起冻结，Markdown 仍沿用支持的热更新路径。

固定版本上游的限制：ACP 在允许切换模型前先解析持久会话的原模型；首次解析遇到 UNKNOWN_MODEL / NO_ADAPTER 就退出，尽管同一方法已经支持后续目录变更后的“当前模型不可用”状态。ACP 进程内模型选择不持久写入请求头；首次修复的零生成模型切换在进程重启后不足以解决问题，14:31真实请求再次失败，QQ随即关闭继续修复。未将该健康检查误报作为最终验收。

最小 core 补丁：在 `@deepseek-ai/dsh-acp/lib/index.js` 导入 `LlmError`；首次解析也仅对 UNKNOWN_MODEL / NO_ADAPTER 使用已有不可用状态，允许宿主显式应用控制台选定的模型。其它首次错误仍抛出。插件无法访问私有 AcpModelControl 初始选择，原生 request/header 也禁止在 turn 外追加，因此本次需要这个小范围兼容补丁；不改历史，不保留退役模型目录项，不发 GLM 请求。

`scripts/apply-dsh-runtime-fixes.py` 绑定固定上游 ref 与完整原始文件 SHA256，检查锚点、拒绝未知/半成品版本、原子安装且可重复执行；`bootstrap-dsh.sh` 在锁定安装后自动应用。原生共享目录回归新增同SID跨两次进程重启、旧模型已移除、零推理修复，以及随后只向有效本地模型发送请求的检查；与故障转移ACP回归2项通过。真实失败会话副本也跨两次进程重启恢复、会话事件完全不变。上游若允许首次恢复时展示不可用模型并切换，升级时应移除补丁并保留这些回归；升级ref或源码变化会强制重新审核补丁。
