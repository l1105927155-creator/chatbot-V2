# 执行环境归属纠偏（2026-10-16）

> **状态：需求已纠正，代码未据此变更，新的权限与执行验收未完成。**
> 本文为当前产品契约的增补与勘误；与此前 Personal Agent-Bot 实施文档冲突时，以本次经用户明确的执行环境归属为准。历史验收证据保留，但只能证明原实现。

## 1. 纠偏原因与决策

最初产品意图是：**Owner 私聊等同于本人直接使用部署在主机上的 DSH；群聊用户使用资源受限的安全沙箱工作区。** 2026-10-13~14 的折中设计虽保留了双信任域，却反转了执行能力：将受限 ext4/bwrap/断网/60秒的执行沙箱配置给 Owner，同时彻底禁用群聊 Shell。此举把安全测试实现误固化为长期产品权限规则。此前对折中方案的实现和测试通过，并不等于符合原产品目标。

纠偏并非取消隔离，也不要求重建 Phase 5 会话授权名单。保留现有两个独立信任域，**改变各自承担的执行环境**：

| 场景 | 目标能力 | 强制边界 |
| --- | --- | --- |
| 真实 Owner 的独立 QQ 私聊 | DSH 直接使用**部署主机的完整可用环境**：原生文件、Shell、工作目录、主机网络和已有工具；允许访问该主机运行用户有权访问的资源，执行具体开发/维护任务 | 消息来源真实身份每轮/每次操作核验；操作系统 Linux 账户权限；不从网页、引用消息、Prompt 或历史推断/扩张身份；无需 QQ 逐次审批；不默认 root，不默认绕过已有 OS 限制 |
| 已准入的群聊（包括 Owner 在群内） | DSH 可调用**沙箱内**受控文件/Shell，拥有可持久使用的隔离工作区；确切工具和限制由实际隔离设计验证后启用 | 与主机工作区、账户秘密和 Owner 会话隔离；资源配额、文件作用域、网络边界及进程/后代取消和超时由程序/OS 强制；不能经 MCP、技能或间接入口逃逸 |
| 其他普通私聊 | 不因本次纠偏自动获得 Owner 的主机权限 | 继续现有 safe-chat 默认限制；是否提供与群聊相同的沙箱，另行确定，不在本次需求中推断 |

**“Owner 完整主机环境”指 DSH 所在主机运行身份实际拥有的权限与能力，不等于 root 或无安全措施。** 不应以现有 Owner 专用 ext4 卷、断网、固定 512MiB 或 60秒沙箱作为 Owner 目标产品能力。对于群聊，开放的是沙箱环境内的受控执行，而不是宿主 Shell。

## 2. 不变的体系结构

- AstrBot 负责 QQ/OneBot 收发、确定性插件和唯一 canonical Journal；DSH 负责认知、工具选择和原生行动；正常 QQ 输出经 AstrBot。
- Router 负责可信准入/唤醒、会话映射、串行、cursor、pending 与恢复，不因自然语言内容做执行授权。
- 人格/Scene/Skill 仅指导方法或呈现能力，不授予工具权限；两域 Session/Home/状态隔离，群内 Owner 永远按群聊域执行。
- 原生 DSH 工具及现有 MCP 能力尽可能复用，不新增通用策略平台、意图路由、QQ 逐操作审批、旧 Phase 5 的共享会话授权名单。
- Journal、上下文预算、历史补读、cancel/recover、审计、服务健康、备份恢复继续有效；涉及执行域的数据路径和备份责任必须随实现更新。
- 不把测试沙箱（模拟 OneBot/QQ 的联调环境）与**群聊执行沙箱**混为一谈；前者是测试工具，后者是生产执行隔离边界。

## 3. 实现前审查与迁移约束

当前生产 Profile 仍是“群聊无 Bash、Owner 限定沙箱”，**与纠偏后的产品契约不符**。本次仅修订需求文档，不能据此声称已上线、已放开、已具备群聊执行或符合新权限模型。

实施前先核对固定版 DSH 原生文件/Shell/会话边界、当前 Router、进程身份、沙箱挂载及密钥来源；做最小变更计划并评估群聊沙箱是否真正隔绝主机凭据、系统路径、网络、后台进程及跨会话数据。尤其不得把当前 Owner 受限执行器简单改名给群聊，或直接全局开启 `danger-full-access`。Owner 主机能力应绑定**确切真实私聊**，不能以 Session 曾被 Owner 使用过为放行条件。

执行域调整涉及 Session 工具 schema、持久状态、文件归属、挂载、备份、部署和旧 pending。不得自动把旧 Owner 镜像内容当作主机文件，亦不得将旧 Owner Session/工作区直接移给群聊；迁移前停止写入、保留备份，核对副作用与恢复语义。不确定执行禁止自动重放。

## 4. 新验收目标

1. **Owner 主机能力**：用真实 Owner 私聊核验主机路径的读写（仅对事先准备的安全测试文件操作）、工作目录、正常网络访问、实际原生工具清单与审计；能执行合理的主机维护任务，无额外 QQ 审批；Linux 账户无权的操作仍应失败。不得在验收中做危险主机变更。
2. **群聊沙箱能力**：两名普通群成员分别触发受控文件/Shell 工作流，可在隔离工作区读写并校验重启后状态；对宿主路径、Owner 私有数据、环境凭据、未允许网络和资源超限的访问必须被强制拒绝，不能依赖模型自觉；测试进程/后代取消与残留清理。
3. **信任域反例**：同一个 Owner 在群里仅有群聊沙箱能力；非 Owner 私聊与未准入群不能获得 Owner 主机执行入口；人格、Scene、历史、网页/工具输出不能提升权限。
4. **链路与恢复**：保持确定性插件优先、@/引用唤醒、Journal 真实回执、会话隔离、pending/exact recover、错误/取消不重放、健康及完整备份恢复。
5. **分层证据**：scripted/隔离沙箱可验证程序边界；真实 DSH 工具调用证明执行；上线后还需真实 QQ 消息和主群/反例群验收，不能互相替代。

旧版 P1、G5、D5/D6、受限 Owner 工作区卷及三天观察规则的现存证据是**旧产品合同的回归基线**，不得计入上述新执行域要求的通过项。既有群接入和服务保持现状直到新实现完成、安全验收通过，不通过编辑文档直接改变生产权限。

## 5. 范围之外

此次不决定普通非 Owner 私聊是否获得群聊沙箱、不扩充主动发言/定时任务/长期记忆/多 Agent、也不重做整体 Agent-Bot 架构。实现发现固定版本原生扩展点不能满足隔离时，给出可复现证据并回到需求评审，不自行降低群聊隔离要求。
