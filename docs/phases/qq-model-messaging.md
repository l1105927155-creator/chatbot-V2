# 模型选择 QQ 原生提及和引用

用户进一步明确：Bot 应拥有原生 @ 能力，由指南引导选择交流对象；可先引用 A 的问题回答，再另发一条 @ B 的转告。本阶段取代上一轮“程序强制每条回复 @ 当前发言人”的普通交流规则。

## 本轮边界

- AstrBot 继续发送原生消息链，DSH 通过工具选择 At 与 Reply；自由正文保持 ACP 原生最终回复，不解析自定义消息标记。
- `qq_send_origin(text, mention_user_ids?, reply_to_journal_id?)` 发送独立消息；`qq_prepare_reply(mention_user_ids?, reply_to_journal_id?)` 只设置本轮最终正文的组件。
- 未设置组件时发送普通正文；设置可整体替换或清空，选项不跨事件或轮次。取消、重置及发送生命周期继续使用原实现。
- `current_group_members(query?, limit?)` 按需确认当前群昵称与 QQ 号。程序在准备及发送时核验群成员，引用限当前会话重置点之后、当前入站消息之前及自身。
- 常驻指南表达交流原则；参数和发送方式在工具说明中；人格与授权边界保持独立。群聊直接回复指明交流对象，接续具体消息可引用，转告选择实际接收者。
- 撤去普通回复、命令、文件的统一自动 @ 和长转发配套提示。宿主故障通知继续按既有规则核验并通知发言人与 Owner，属于确定性故障处理。

不扩展跨群/跨私聊发送、成员权限、主动后台任务或模型自主授予 Owner 身份。求助时机可由模型决定，但按配置发现 Owner 的专用能力另行按需求接入。

验证与实际部署见[验证记录](../qq-model-messaging-validation.md)。
