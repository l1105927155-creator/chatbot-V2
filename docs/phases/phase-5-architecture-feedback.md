## 1. 威胁模型决定

owner 是用户本人，不向其它人开放 owner 控制；成员编辑能力只在 owner 明确开放的范围内。
本阶段不以 owner 或本机进程恶意配合普通成员、在授权检查与实际 I/O 之间主动替换文件或祖先目录为威胁模型。
不要求针对这种并发替换提供固定 inode/目录句柄级保证，也不为它增加上游补丁。

路径替换测试证明原生路径执行存在竞态窗口，不证明真实普通 QQ 成员拥有替换权限或可以利用该窗口。
保留测试和事实记录，但不再将此项作为本阶段产品接入阻塞或必须修复项。
也不宣称并发竞态已消除；可信维护进程发生路径替换时，仍属于已知保证范围外的情况。

继续防止普通成员通过相对路径、`..`、已有符号链接或间接工具越界。
不能从某个文件的读取/编辑许可推导出父目录、链接、任意文件或通用 shell 的控制权。
如果启用的成员能力本身允许制造指向未授权对象的链接/目录替换，则必须拒绝该越界能力，不能用“owner 可信”豁免成员绕过。

普通编辑是在 owner 允许的资源范围内修改内容；无需把它自动视为检查期间替换目录拓扑的权限。

## 2. 允许的实现边界

优先使用固定版本公开工具执行钩子和必要的原生 FS provider 扩展/装饰，委托原执行。
按上述威胁模型验证资源路径和实际操作效果，不要求 `/proc/self/fd` 对象绑定方案成为产品实现。
保留原生工具输出、sandbox、版本检查、原子发布与取消语义，不能复制整个文件执行器或改成 V2 文件 MCP 工具。

本反馈不批准修改上游 core、使用私有测试 hook 或建设权限平台。
如公开接口连上述边界都不能满足，记录具体不足并提出最小补丁方案供再次评审；
不要因为已排除的恶意并发替换继续扩大修改面。
Linux readText 句柄候选不证明其它操作或平台通过，既有运行证据仍按原范围保留。

## 3. 附带访问的处理意见

采用按实际效果分别检查的保守规则：

- overwrite 读取并返回旧内容时，需要 read + write；仅有 write 而原生操作必然读取旧内容时直接拒绝。
- edit 需要 read + write。
- 创建文件不能隐含创建父目录权限；缺失父目录且没有明确创建权限时拒绝，不自行增加目录/通配授权需求。
- 本阶段不要求开发“无读取覆盖模式”。

owner 按 owner 分支允许部署已启用的系统操作，无 QQ 逐次确认；以上范围组合针对普通成员检查。

## 4. 可信来源的最小接入意见

接受工作区外、普通成员不可读写的私有运行期来源文件作为候选事实传递方式，不视为已经通过验收。
它只传递 runtime epoch、session、真实 requester、turn nonce 等必要事实，不存储放行结果或角色平台状态。

原生端必须把来源关联到实际当前 turn；文件存在或 session 相同不足以认可旧调用。
每次实际操作继续读取最新持久名单。
发布和清理应覆盖正常结束、异常、取消和重启；来源缺失、不匹配或过期时拒绝。
不能在底层工作仍运行时提前切换/清除来源并让其它 turn 接管。
私有来源与授权配置不能被普通成员的文件授权覆盖。

未验证来源绑定的后台、派生 Agent 和持久执行入口在最小部署中不开放，不能自动继承 owner 身份。
若扩展接口无法建立当前 turn 的可信绑定，记录原生缺口，不能靠 prompt、时间猜测或任意加字段宣称已解决。

## 5. 下一步与验收

可以继续验证并实施可信来源、会话名单持久化/并发更新、owner 编辑和逐操作检查。
不恢复审批工作流，不重建 session/cursor，不扩张 Router 的业务能力知识。

开发验收至少包含：

- 静态链接与路径越界拒绝、精确 persona 读取、其它文件及未授权写入/删除拒绝。
- overwrite/edit 附带读取与缺失父目录行为。
- 当前 turn 来源绑定、异常/取消清理、过期来源拒绝及普通成员不能编辑来源/名单。
- 同群身份切换、不同会话并发、同轮名单变化、撤销及重启持久化。
- owner 原生工作区写入/删除、名单编辑、拒绝后会话继续，无 QQ 审批。
- 原有 MCP 契约、消息 journal、session/cursor、命令穿插与无推理启动回归。

不把恶意并发路径替换测试计为本阶段已修复，也不把它计为当前产品验收必须通过项。
