# 群模型设置即时生效与会话重置

用户要求 `/provider` 和 AstrBot 插件页切换模型后，后续会话操作同步使用当前设置。

11月4日17:22，测试群1055300305的 `/new 跳过记忆` 在新会话模型配置阶段失败。控制台保存的是 `wb/deepseek-v4.1-flash`，旧 `conversation_model` 表仍保存已退役的 `wb/DeepSeek-V4-Flash`。控制台模式下，模型切换有意只写控制台这一个权威配置；聊天、定时任务及记忆已读取控制台，但重置遗漏迁移，仍读旧表。只读复现确认旧值会被当前原生目录拒绝，新值通过；原会话映射保持。

在现有 `ChatService` 内统一当前模型读取入口。启用控制台时，每次操作直接读取当前持久配置，不读取旧路由表；控制台缺少群配置时明确报错。只有未启用控制台的兼容环境使用旧表。聊天、重置、模型管理、压缩和定时任务共用此入口；记忆原本逐批读取控制台，保持原行为。保存成功后启动的新操作使用新模型，不重放已发出的请求，不通过双写旧表制造第二份权威配置。

重置仍先配置新会话、最后通过CAS提交映射；未提交的新会话会关闭，原映射保留。补充失败阶段和安全异常类型日志，审计记录异常类型；不记录原始请求、供应商正文或密钥。

验证使用真实 Journal、SQLite StateStore 和文件 ConsoleStore，保留失效旧路由，并禁止控制台模式读取旧表。覆盖两种切换入口、同一服务实例立刻聊天及重置、重建实例后重置和压缩、缺少控制台配置拒绝降级、跨群隔离、记忆和定时任务；既有140项回归和新增2项集成测试通过。新用例另在暂存的冻结生产服务代码复验通过，保留运行版本的其它修改。
