# 群聊记忆系统：需求与验收草案

> 状态：最小闭环已实现并通过隔离及真实模型小样本验证；2026-10-27已接入生产当前7群，见[生产接入](group-memory-deployment-2026-10-27.md)与[实施阶段](phases/group-memory-2026-10-26.md)
>
> 本文记录已确认的产品规则和验收范围。以最新用户说明为准；旧草案中的核心背景自动注入、线上旧历史导入和记忆可信度门槛已撤下。本阶段采用薄自研存储与现有原生接口，避免迁移旧插件不符合需求的业务。

## 1. 目标与已确认原则

让 Bot 在各群工作区形成跨 Session、跨 Persona 的连续记忆：它能记住自己如何理解过往经历，按需回忆，并在新交流或质疑中重新理解。保留功能覆盖，以接入、改造和维护总成本最小的方式实现。

- **Journal 是群内消息发生记录；记忆是 Bot 对经历的理解。客观事实需验证，主观理解随意发挥。** 客观陈述按可核对来源支持的主体、动作、时间和完成状态记录；成员说过、邀请或推测某事，不直接证明该事件发生。Bot 可以自由形成主观判断、印象、偏好和感受，保留推断的性质；其中涉及的客观前提仍须有依据。本条于2026-11-03按用户要求明确，同时适用于记忆正文与每条claim。
- 模型日常可以依自己的记忆交流，不要求每次先查证、报告不确定性或打可靠性分数。遇到质疑、矛盾或确有核实需要时，再查来源并决定是否调整理解；允许按当前群真实记忆 ID 定点核实跨重置来源。
- **不要求模型生成 confidence，不以置信度、可靠性等级或其阈值决定能否记住、召回、修订或遗忘。** 不迁移旧版的候选可信度审核链。
- 记忆权重用于保留、强化、淡忘与召回优先级，**不表示内容为真的概率**。具体计算及模型参与方式待方案验证；不要求用户逐条标权重或固定记忆。
- 每群一份记忆，所有 Persona 共享。当前 Persona 影响选材、理解和维护；切换 Persona 不分库、不清空经历。
- 记忆归对应群工作区所有，随工作区备份、迁移、恢复和清理；不在宿主另留可继续生效的记忆副本。普通群成员的发言不构成数据库写入命令；日常维护由 Bot 自主决定。Owner 保留后台手动编辑能力，用于调试和维护。
- 当前所有已准入群启用；未来新增群的启用策略尚未决定。群间以及群与 Owner 私聊间隔离。
- 线上从启用时的 Journal 高水位开始，不导入启用前历史。隔离沙箱可导入历史测试材料。

## 2. 内容选择、模型职责与程序职责

群友偏好、共同经历、群文化、持续事项、Bot 的印象与感受，是可供模型选择的内容方向，**不预设必须分别建立表、分别运行模型或每类都产生记录**。人物关系、资料知识和做事经验的独立能力尚未确认，不因前轮候选表而自动纳入。

记什么、粒度多细、怎样理解、如何合并或遗忘，主要由模型结合人格、上下文和简短指南决定。程序负责让这些决定能够持久化、检索和执行，并保证来源归属、隔离、事务、任务触发和资源边界。分类/标签是否需要作为索引由实际检索验证决定，不先建设复杂分类体系。

**发言归属必须保留，不把第三人的说法当作当事人信息的直接更新。** 例如：

- A 说自己的工资攒起来了。
- B 说 A 没攒，而是拿去充值游戏了。
- 应能记成“A 说自己攒了工资，后来 B 对此反驳，说 A 拿去充游戏”。不能仅合并成“A 先攒工资，后来充值游戏”，也不能无声把 A 的陈述替换成 B 的版本。

Bot 可以依据上下文改变自己的理解，但保留不同说法的归属和来源；不由程序按发言者身份直接裁决哪方内容为真。A 后续自己的更正也应保留变化过程，而非改写原始 Journal。

## 4. 自动任务前置能力

用户新增了独立的自动任务需求：助理可自主创建任务，程序在条件满足时触发。记忆整理是任务的一种用途；示例包括累计 99 条历史触发整理，以及成员生日当日 9 点发送祝贺。示例不等于已经确定所有触发类型、默认数值、时区、授权或发送规则。

**2026-10-26 原始范围决定**：自动任务长远包含复杂、自定义条件，首批采用手写条件实现每日22点/99条群友消息检查；不预建通用条件引擎或额外复读/唤醒场景。该每日整理入口已被下面的新决定取代，历史过程见[自动任务阶段](phases/automatic-tasks-2026-10-26.md)。

**2026-10-29 当前决定**：日常整理由记忆插件的后台增量能力接管，依据新增群友消息门槛或最长等待触发，两者可在记忆页持久配置；当前7群启用99条/1800秒。Bot不计入门槛，仍包含在内容内。`/new`补齐未整理尾段，不受消息门槛限制；失败保留上下文和未完成范围，显式跳过不推进记忆游标。后台失败/取消后暂停，不因新消息或重启自动重试；Owner可显式重试。旧全局22点及工作区内置`daily_memory`清理，保留自建任务与日记。见[后台增量阶段](phases/memory-incremental-2026-10-29.md)。

当前实现目标是一处原生调度接入加明确的记忆整理条件/动作；新增实际场景时再加相应检测代码。复杂条件的长期需求不能被解释为本轮必须预建通用平台，也不能声称当前这一个场景已经实现任意条件检测。手写条件指开发者维护的程序逻辑，不自动授权模型生成并执行任意条件脚本。

- 先核实固定 DSH/AstrBot 的原生定时/任务能力和扩展点，再提出最小接入；不先造通用编排平台或只为记忆写一套重复的调度器。
- 创建、触发、执行结果、重复触发处理、取消及重启后的状态应可检查。具体持久化/漏触发/补跑策略需要技术验证和产品对齐。
- 对时间、计数等可直接计算的条件，由程序判定，不依赖模型每条消息都推理。复杂条件需区分事件/状态的程序检测与语义理解；是否允许模型辅助判定、触发频率及成本边界待实际场景对齐，不能默认每条消息额外调用模型。
- 记忆整理任务只整理记忆，不发送 QQ 消息；生日祝贺属于另一个可发送任务，仍经 AstrBot，不能让记忆任务隐式获得发送权限。
- **允许 Bot 自主创建任务（2026-10-26 已确认）**：可以从当前交流、经历和已有目标判断需要一个后续任务，不以用户必须明确说出“创建任务”为前提。直接要求创建是明确指令；自主创建则包含 Bot 对任务必要性的判断。该授权不要求无缘由创建任务，也不要求新增持续运行的模型思考循环。任务触发/执行权限、生日数据来源和时区仍待对齐，不自行以昵称、Persona 或消息正文授予系统权限。
- **自主通知小额度试用（2026-10-26 已确认）**：采用每群每天最多发送 1 条自主通知、最多保留 3 个待执行自主通知任务的试用额度；相同目的不重复创建。成员明确主动要求创建的任务不计入这项自主通知额度，不将本条解释为取消程序既有权限、容量或发送边界。需保留创建依据和类别，分类不能只凭模型自称“用户要求”。通过 AstrBot 插件页查看/取消，并可单独关闭自主通知。日界时区及限额命中后的处理仍待确定。

## 5. 整理、重置、召回与维护

### 5.1 后台整理

只消费当前群 canonical Journal，包括群友消息和已确认成功发送的 Bot 消息。来源区间固定、有界；每群整理游标独立于聊天 Session 游标。记忆变更和整理游标须一致提交，失败、崩溃、重复任务不丢失区间或重复机械归档。

整理读取该群有效 Persona；是否还读取待重置 Session 的总结或上下文，以及其与 Journal 的职责，待技术核实。整理可零变更，不因一次任务运行强行制造记忆；不逐条消息额外发起模型调用。保留来源、所用 Persona/模型版本及成功/失败证据；并发人格变化策略待验证。

2026-10-26 核实：Journal 本身包含已捕获的当前群聊天消息，并非只含较早历史。它不记录完整 DSH Session 内部状态，如工具调用/结果、压缩摘要和未送达 QQ 的中间输出。当前模型上下文又是有预算的投影，可能省略或压缩 Journal 内容。因此“补充当前上下文”不是补上 Journal 天生缺少的当前聊天，而是引入另一类执行/压缩材料；两者都不能被称为模型脑内想法。本阶段采用 Journal + 当前 Persona + 必要的既有记忆，以当前人格形成或修订理解，不读取前台 Session 内部材料。额外保留当时未公开表达的感受仍属后续决策。

### 5.2 `/new` 与 `/reset`

目的仍是清空当前模型会话上下文。重置前触发记忆整理以减少未归档经历损失，持久记忆不因此删除；新 Session 不自动加载核心记忆、群友档案或旧经历摘要。模型可在后续具体需要时调用记忆检索。

**2026-10-26 已确认命令合同：**

- `/new`：先整理记忆；整理成功后清空上下文。整理失败则回复失败，阻止清空上下文，不自动重试，也不为这次失败安排后台重试。
- `/new skip_mem` 或 `/new 跳过记忆`：不整理记忆，直接清空上下文。
- `/reset` 沿用既有 `/new` 别名关系，接受相同参数。群记忆只适用于群运行域，Owner 私聊和 safe-chat 不因未安装群记忆而被阻止重置。控制台重置入口本轮未改变。
- 超时、模型返回不可用、存储失败和程序异常都可能导致整理失败；不能未经运行证据声称具体根因，也不能假定重试必然恢复。

整理与重置的先后顺序、冻结来源上界、聊天并发、重复重置和重置取消须验证。整理未接入或不可用时，应如实报告并阻止默认群命令重置，不能把无操作当成记忆已保存；显式跳过参数仍可使用。清空上下文不等于禁止已授权的按记忆 ID 定点核实旧来源。

### 5.3 按需与模糊召回

查询绑定当前群，不接受任意群 ID、文件路径或 SQL。返回相关记忆及来源标记；无匹配就返回空。

候选最小方案：一个有界查询接口内部完成精确与模糊匹配并返回少量结果；不另起模型 Agent 做联想，不以自动反复改写查询作为默认召回流程。模型何时调用、未命中后是否允许追加查询，以及能接受的实际延迟待验证/对齐。模糊召回是检索能力，不保证或强制每轮触发。

### 5.4 自主维护与权重

合并、重新理解、撤回、归档与遗忘由模型在整理/维护中自主决定；不增加前台当场记忆决策。权重可利用重复经历、持续性、时间及模型判断，但不把权重当作真实性，也不直接把每次检索命中当作新证据。

反复积累的重要经历不能仅因一周未提及就被机械遗忘；具体规则用长期样本验证，暂不预定衰减公式。已撤回理解不因重复处理同一来源自动复活；新证据可形成新理解。遗忘不修改原始 Journal，也不承诺擦除模型已在当前 Session 看过的信息。

## 6. 来源、存储、插件管理与媒体

- 每条记忆有稳定 ID、内容、相关成员标识（按稳定 QQ 身份，不按昵称）、来源指针、创建/维护时间、状态及必要修订信息。无需强制划分“客观事实表/主观印象表”，不引入 confidence 字段。
- 来源指针至少绑定 `platform_id/bot_id/conversation_key/journal_id`；有平台 message_id 时保留辅助定位。不仅凭模型给出的 ID 就承认来源有效，宿主验证当前群内真实存在的消息。原文不另复制成第二份聊天账本。
- **已确认来源查询边界**：MCP `history_recent/before/search` 继续由宿主绑定本轮群身份及重置下界，模型无权传入数据库路径、SQL 或另一个群身份；群沙箱不获得宿主 Journal 文件访问权。用户已授权 `memory_sources` 按当前群真实记忆 ID 查询，由宿主解析和校验其来源后每页最多返回 20 条关联消息，可跨重置核实。没有开放任意旧历史、邻近消息扩展、宿主文件或其他群/私聊。
- 群工作区内持久化、随卷备份和恢复；删除工作区后不再从宿主残留副本继续检索。现有手工 `memory/` 资料不被无声覆盖。
- 已核实：群应用只能写自己的 data，但 Owner/编辑者的 Bash 可写整个群工作区，控制台文件接口也没有记忆目录特例。不能据现有 group_app 宣称记忆免于直接编辑；需要结合本轮授权的后台手动编辑，明确程序入口和资产完整性。不是所有手动变更都应被当作攻击，也不能把普通聊天转成任意写库入口。
- 管理入口是 AstrBot 插件页：浏览/搜索、手动编辑、按群启停、导出及清理、运行状态和消耗。具体字段与完整恢复颗粒度待最小方案确定；编辑结果须与后台整理并发安全，不静默覆盖，也不能篡改 Journal 来源记录。
- 媒体记忆为保留需求，受识别能力前置约束。未识别的图片、语音、文件只可记录可证元数据，不编造内容。记忆层不顺带替代媒体识别项目。

## 8. 验收重点

复用现有隔离 OneBot/AstrBot/DSH 沙箱，不以 scripted 模型通过冒充真实记忆效果。至少覆盖：

1. 人格影响选材和理解；无需 confidence 输出仍能完整整理、存储与召回。
2. 记忆可存在误解；被质疑后查询来源并自主修正，不因质疑者身份或断言直接覆写。
3. A 的陈述与 B 的反驳保留各自归属；不合并成 A 自身的时间变化。
4. 多条重复经历能合并并保留来源，不因同批重试强化多次。
5. 自动任务达到条件才运行，重复触发、故障重启和取消不丢不重；记忆任务不能发送 QQ。
6. 默认群 `/new` 整理成功后才重置；失败/超时不变更原 Session/历史起点、不自动重试；两个跳过参数都不调用整理。无权成员不能利用参数绕过控制权限，未知参数不能开始重置。重置后没有核心背景自动注入，按需检索仍可用。
7. 模糊问法能找到相应经历；未命中时不无界追加模型调用或长期阻塞普通聊天。
8. 自主修订/淡忘/强化生效，重要重复经历不会因短期不活跃机械消失；召回次数不伪装成事实证据。
9. 两群同名成员、跨 Persona、跨 Session、重启和工作区备份恢复不串群或分片。
10. Owner 插件页手动编辑与后台整理不静默覆盖；来源标记仍有效，原始 Journal 不被修改。
11. 线上不导入启用前历史，沙箱历史导入不混入生产；媒体未识别时不虚构内容。
12. 日常交流不因记忆增加不必要的检索步骤；真实模型与端到端延迟、失败和消耗分别报告。
