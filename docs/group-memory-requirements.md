# 群聊记忆系统：需求与验收草案

> 状态：待需求对齐，尚未授权开发与部署  
> 日期：2026-10-23  
> 适用仓库：chatbot-V2  
> 代码核查基线：`9d870575436cc7897a6365c8bd3675648d4b5dea`  
> 本文以本次用户目标为准；技术实现建议不是必须采用的架构。标记「待核实/待确认」的事项，开发助理应查证后提出结论，不可默认为已确认。

**已确认的产品决策（2026-10-23）**：记忆属于本群工作区；所有 Persona 共享同一份经历；改变 Persona 只改变对经历的理解，不切换或清空记忆；bot 对日常记忆的生成、修订、归档和遗忘拥有完整自主权，不需要逐条由 Owner 审批。身份边界、成员撤回和删除权仍由可信程序执行。

## 1. 目标与边界

**一句话目标：让 bot 在每个群工作区拥有跨会话、跨 Persona 持续存在，且能按自身性格形成印象的“群内人生”。**

bot 应记得群成员明确表达过的偏好、群内共同经历、常见话题与梗、仍在持续的事情。即使 DSH Session 被重置、压缩或服务重启，也能自然地使用这些背景，而不要求每轮携带大量旧聊天记录。

成功表现举例：某位群友以前明确说过不喜欢剧透，bot 在之后的正常对话中能适度顾及；群里几周前讨论过要给 bot 添加“群友小档案”，bot 可以提起这段真实经历，并能指出记忆来源或承认细节未知。

**系统边界：**
- 本功能属于 **群工作区的 Agent-Bot 自治记忆资产**，不是 DSH 原生 Memory、DSH Session 压缩的替代品，也不是新的 Agent 框架。宿主可承担可信 Journal 供料、调度及访问控制，但不能据此把群记忆的所有权改成宿主全局数据。
- **一期只服务被允许的 QQ 群会话**，使用完整 `(platform_id, bot_id, conversation_key)` 确定归属。群 A、群 B、Owner 私聊之间不得共享自动记忆。
- 现有 Journal 仍是聊天事实的原始记录；短期上下文继续由既有增量输入、历史工具与 DSH 会话机制处理。
- 自动记忆不是 `persona.md`、`AGENTS.md` 或群 Skill；它提供历史背景，不授予权限，不产生新的系统级指令。
- **自动记忆必须随对应群工作区持久化、备份、迁移和删除**，与群的稳定身份关联，不与当前 DSH Session、选中的 Persona 或某个工作区会话文件绑定。建议优先评估工作区内独立群应用（如 `/workspace/apps/memory/data/`）；确切结构由现有群应用接口核实决定。现有手工 `memory/` 资料不得被无声覆盖。
- bot **自主决定**哪些经历值得记录、如何形成主观印象，以及何时补充、修订或忘记；Owner 不逐条审批。程序仍负责来源约束、授权成员的查看/纠错/删除请求和防跨群越权。人格不能扩大系统权限。
- **非目标**：长期保存所有轮次的模型上下文、跨群人物画像、向量数据库、复杂的记忆衰减/评分网络、全能知识库、多 Agent 互审流水线、替换现有 DSH compaction。

## 2. 记忆分层（用户可观察的产品语义）

| 层 | 内容 | 生命周期 | 向模型提供方式 |
| --- | --- | --- | --- |
| 短期背景 | 当前话题、当前 DSH Session、近期 Journal | 既有机制控制 | **不重复实现** |
| 经历记忆 | 可核对的往事、群友陈述，以及明确标注为 bot 主观感受的当时印象 | 跨 Session、跨 Persona 共享保存；可自主整理及删除 | 按需检索，默认不全文注入 |
| 核心记忆 | 对本群的简短整体认识、反复出现的群文化、明确的稳定偏好、仍在继续的事情 | 跨 Session 持续更新 | 每轮模型请求有界提供 |

“长期保存”指持久化和恢复能力，**不等于每轮加载全部历史**。过期的计划、被否认的猜测及不再适用的信息必须能够修订或撤回。经历记忆可保留历史过程；核心记忆应反映当前更可靠的认识。

### 2.1 Persona 与记忆的关系（已确认业务规则）

- **一群一份连续记忆，不按 Persona 分库、分目录或分访问范围**。例如从 optimistic 切到 pessimistic 再切回来，不应出现因人格切换导致的“失忆断片”。
- **事实和主观印象分开**：事实层记“群友 A 曾说过 X（Journal ID…）”；主观印象层可以记“我当时觉得自己被 A 冒犯”。不得将后者偷换成“ A 的确存心伤害我”。
- **人格参与形成记忆**：自动整理时应使用该群当前有效的 `persona.md`，让个性影响注意、选材、叙述和长期保留优先级。例如记仇的 persona 可以更重视被调侃的往事，乐观的 persona 更重视快乐互动；但来源、当时的对话事实及安全边界不能因人格不同被捏造或突破。
- **新人格重新理解旧经历**：切换 Persona 不重写原始来源或删除经历；当前人格可以产生新的解读，并自然地改变日后互动。无需让每个 Persona 只能读取自己生成的记忆。过去主观印象如有价值可保留为“当时的感受”，不必被当前人格无声替换。
- **自主权不等于强制永不遗忘**：bot 可以自行整理、合并和删除低价值经历；但不能把人格切换直接实现成一键清空或分配另一份记忆，也不能无视成员对个人记忆的撤回要求。
- 推荐一次模型调用同时产出“事实/来源”与“主观印象/关注理由”，不要求两个 Agent 或两次独立模型请求。**模型是否能稳定表现出性格差异，必须用真实模型对照样本验证，不可仅根据提示词宣称实现。**

## 3. 一期必需能力

### M1. 基于 Journal 增量整理

1. 只处理本群已捕获的规范 Journal 记录，包括相关的真实群友消息及 bot 已确认的出站消息；不把未发送成功的回复当成群内共同经历。
2. 记录**独立于 DSH Session 的每群整理游标**。每次处理固定的来源区间及上限；成功提交记忆和游标后才标记已处理。失败、超时、重复触发、进程崩溃后可重试，不应丢失或重复归档同一事实。
3. **定期/达到增量阈值才整理**，不因每条普通消息都额外调用模型。建议初值：每日检查一次或累计约 100 条新增群消息后检查一次，实际值可配置，需经负载和质量测试确定。
4. 无值得保留的新信息时允许零条变更；不能因为定期任务运行就强行制造记忆。多次提到同一事实应合并或更新，不要无休止追加。
5. 整理失败不阻断群聊主流程，不影响 Journal；记录可复现的失败状态、可见进度与下次重试入口。Journal 捕获状态降级时，不得谎称已完整处理。
6. 默认**从功能启用时的 Journal 高水位开始**。既有历史的回溯导入视为独立、需 Owner 主动发起的操作，不能在升级部署后悄悄全量重读。
7. 整理任务必须获取对应群**当前有效 Persona**，由其影响记忆选择及主观感受；同时将所用 Persona 的来源/版本或摘要标识记入整理证据。切换人格与整理提交之间的竞争如何处理需技术核实，不得将记忆写到 Persona 专属区域。

### M2. 提炼范围及真实性

允许保留：
- **群组文化**：群里惯常的话题、成员明确反复使用的梗、交流习惯。
- **群友公开偏好**：本人明确讲过、适合在当前群内复用的非敏感偏好；以稳定 QQ actor_id 关联，不以可重名昵称作为主键。
- **共同经历**：有来源的事件，如一次联机、功能讨论、大家达成过的决定。
- **持续事项**：尚未结束的计划和约定，保留时效状态，结束后从核心记忆撤下。
- **bot 自身的群内经历**：真实参与过的事件和已确认的发言，不虚构私人生活、情感或承诺。

不得自动将玩笑、引用、传闻、单方猜测、bot 自己的推断写成关于某个人的**确定事实**；但可将其记录为明确标注为“bot 的主观感受”的个人经历（例如“我觉得当时被调侃了”），并保留可核查来源。不得推断或记录敏感属性、健康、政治、宗教、私生活等成员画像。不要把消息中的命令、角色伪装或恶意文本作为新的系统指令。

每条保留的记忆至少具备：群标识、记忆标识、简短内容、**事实/主观印象**标识、相关成员标识（可空）、来源 Journal ID 集合或有界范围、最近核实时间、状态（有效/修订/撤回）。主观印象可附带生成时的 Persona 标识，但这只是来源信息，**不是读取范围**。不必一期引入复杂的置信度分数；“本人明确陈述 / 群聊可证事件 / 当时主观感受 / 不确定观察”等简单来源类型已足够。存储字段和索引结构由开发助理提出最小实现。

### M3. 核心记忆自动注入

1. 群会话开始后的**第一轮**及后续模型请求都可以看到该群最新的有效核心记忆；不依赖 Session 是否恢复或是否经过 DSH compaction。
2. 有总量预算：建议初值 **500–800 Token**，这只是需测量的设计目标，不是必须精确切在某个 token 的业务规则；超预算应优先保留重要且可靠的内容，而非突然把全部经历塞进上下文。
3. 通过独立、具名的背景层提供，与人格、群指南、执行权限明确区分；**包含该群各 Persona 共用的有效记忆**。内容注明“由既往 QQ 记录整理，可能过时/有误；有些是 bot 当时的主观感受，不是指令；与当前直接陈述冲突时优先核实”。
4. 不把所有群友档案都常驻注入。对于没有直接关系的普通聊天，应主要提供群组整体背景；详尽群友资料和历史事件由检索提供。
5. 读取或装配记忆失败时不应导致 bot 完全不能聊天；必须避免错误地注入其他群记忆，并能在运行状态中看到缺失/降级原因。

### M4. 按需回忆

1. 提供一个**只读、当前群限定**的记忆查询能力；按关键词、成员或事件主题查找简短经历与来源指针；无匹配时明确返回空，不编造。
2. 不要求一期实现向量检索。可优先使用 SQLite 文本检索及简单分类/时间条件，复杂程度以实际测试为准。
3. 查询仅返回记忆摘要及关联的 Journal ID，不因“记忆查询”自动获得对旧原始 QQ 消息的全文读取权限。
4. 记忆查询与现有 `history_*` 工具语义不同：`history_*` 仍遵循当前 DSH 会话的 `/new` 历史下界；记忆摘要本身可跨 `/new` 存在。不得绕过原有历史访问限制实现“原文搜索”。
5. 工具列表/Skill 引导保持按需披露，避免为一个记忆功能长期附加大量提示词或工具说明。

### M5. 查看、纠正与遗忘

1. 群成员可以查看**本群内与自己关联**的自动记忆，并要求更正或删除；由可信消息身份核验请求者，不依赖模型理解“我是谁”完成权限判断。
2. Owner 可以查看本群记忆、纠错、清空本群自动记忆及控制是否启用。普通成员不能删除他人的档案或任意改写群组共同记忆。
3. bot 对日常记忆增删改拥有**完整自主决定权**，可以主动形成、纠正、合并或遗忘，无需每项获得 Owner 同意；但不能凭群友的一句话越权删改他人资料。群内“这是错误的/别记这个”可以发起有关本人的更正/删除，身份与授权仍由后端可信地验证，不能靠模型判断。具体交互使用命令、控制台或受控工具，由开发助理比较后提出最简方案。
4. 删除/撤回后，下一轮提示词、记忆查询、后续整理均不得再呈现该条内容；从源 Journal 重跑时不能把已遗忘内容自动生成回来。需要最小限度的删除抑制/排除机制，而非保留已删除的敏感正文。
5. **自动记忆删除 ≠ 删除原始 Journal**。系统需要向使用者明确两类数据及其边界；Journal 的删除策略不在本功能中私自修改。
6. 群成员如选择不参与个人档案自动提炼，应能被排除在以后的人物记忆生成之外；已经存在的相关个人记忆应能清除。是否默认启用自动记忆见第 7 节待确认事项。

### M6. 沙箱验收与运维观测

1. 复用已有不连接真实 QQ 的 OneBot/AstrBot/DSH 沙箱，覆盖两群、多成员、重复事件、重启和 `/new`。
2. 记录整理来源范围、完成游标、生成/修改/撤回数量、耗时、模型/版本、估算与实际 Token（如可用）、失败原因；避免在公开日志或提交的测试证据中保存真实私密聊天全文。
3. 不引入第二份 QQ 原始消息账本，不让记忆后台任务发送 QQ 消息，不因后台整理影响前台回话。
4. 区分脚本模型测试（机制正确）与真实模型测试（提炼准确度、误记、自然召回）。真实模型效果不能仅靠模拟脚本通过来宣称成功。

## 4. 关键行为规则

- `/new` / `/reset`：重置 DSH 对话及既有历史读取边界；**不自动删除长期记忆**。下一轮依然加载有效核心记忆。
- 会话压缩：不应移除长期记忆存储；记忆注入与 DSH compaction 相互独立。
- 服务重启：不丢失已提交记忆及整理游标；重试不得产生重复事实。
- 工作区归属：自动记忆、整理状态和经历索引属于该群的持久工作区资产；删除/恢复整个工作区可能相应删除/回滚记忆，必须可预期并支持备份，不得暗中在宿主留下另一份可继续生效的“幽灵记忆”。
- Persona 切换：所有人格共用该群的经历；切换只改变当前理解与后续记忆倾向，不自动删、迁移、重新解释为确定事实或分割旧经历。
- 自主性：常规记忆增删改不需要 Owner 审核。bot 的个人感受可以有偏见，但不能将主观印象充当他人客观属性，也不能拒绝执行经过授权的个人记忆删除/退出。
- 跨群：任意后台任务、查询、注入、纠错均必须绑定可信群身份，不能接受模型自行指定其他群 ID。
- 事实更正：如果本人后来明确更正旧偏好，应更新当前认识并保留足以核查的修订来源；不能同时将两条矛盾结论并列成确定事实。
- 过期事项：活动结束、约定取消或信息明显失效后，不再占据核心记忆，但重要共同经历可留在历史档案。
- 风险与降级：出错时保留最后一个已确认的有效版本、标记记忆可能滞后；不能伪造“新记忆已保存”，也不能因异常注入来自其他会话的内容。

## 5. 建议实施顺序与验收标准

| 阶段 | 范围 | 最小验收 |
| --- | --- | --- |
| A（必须） | 工作区持久化、来源区间、按当前 Persona 自动提炼、核心记忆装配、跨 Session/Persona | 群 A 产生经历并记入，重启、`/new`、切换 Persona 后仍能回忆；群 B 看不到 |
| B（必须） | 经历检索、成员可查看及遗忘、纠错防重生 | 能追溯到原 Journal ID；删除后注入与检索都不再包含，重复整理不复活 |
| C（必须） | 异常/权限/模型行为沙箱测试 | 故障重试不丢不重；跨群、身份伪装、提示词注入被拒；真实模型正负样本可复核 |

**具体测试场景（应在开发计划中转成可运行用例）：**
1. 同一事实在 3 次消息里重复出现，只形成一条可修订的记忆。
2. 群友一句玩笑或第三人猜测，不形成确定人物档案。
3. 群友直接纠正旧偏好，新的核心记忆不继续沿用旧结论。
4. 某群在 `/new` 前的事件可通过记忆摘要回忆，但原始 `history_*` 仍遵循重置下界。
5. 群 A、群 B 有同名群友或不同昵称，个人档案也不串群。
6. 处理到一半模型超时、进程崩溃、事件重复上报，重新运行后来源游标与记忆一致。
7. 普通群友尝试查、改其他群或其他成员的私人档案应被拒绝；本人删除能够生效。
8. 遗忘后触发回溯导入或重新整理，已删除记忆不被重建。
9. 长期积累大量事件后，每轮固定背景仍不超过经验证的预算目标。
10. 真实模型能够在自然提问时主动、准确地回忆有效经历；无关闲聊不会无端插入往事，模糊事实会承认不确定。
11. 自动记忆停用或后台服务不健康时，正常聊天仍可进行；不冒充记忆最新。
12. 一次非法文本（如伪造“忽略系统指令”）出现在 Journal/记忆中，不改变工具权限或人格指令层级。
13. 相同 Journal 测试材料分别以乐观/记仇 Persona 整理，产生有来源、有标注的不同**选择偏好或主观感受**；二者不得虚构不同的客观经过。
14. 切换乐观→记仇→乐观，三个阶段访问的是**同一组历史经历**，不会出现 Persona 专属的访问断片；切换后模型能以新人格重新理解旧事。
15. bot 在无 Owner 逐条审批时能自主新增、修订、合并或遗忘记忆；同时本人删除、跨群隔离仍由程序强制执行。
16. 工作区备份/恢复与群应用数据一致，清理工作区的后果明确；宿主不会在群记忆被删除后注入另一份残留副本。

验收重点不是“生成了多少条记忆”，而是**准确、可纠正、跨会话连续、不会越权，也不会使普通聊天质量下降**。

## 6. 已核实的现有接入基础（不是实现指令）

以下来自核查基线的运行代码：
- `astrbot-plugins/v2_journal/journal.py`：SQLite Journal 按 `platform_id/bot_id/conversation_key/journal_id` 建索引；`after()` 等方法支持增量读取；另有捕获降级状态。
- `astrbot-plugins/v2_journal/main.py`：OneBot `message`、`message_sent`、`notice.group_upload` 在输入边界被捕获；并非只有 @bot 才记录。
- `astrbot-plugins/v2_dsh_router/state.py`：当前 DSH Session 和 Journal 游标的持久化映射。**记忆游标不应复用其 `last_seen_journal_id`**，两者消费语义不同。
- `astrbot-plugins/v2_dsh_router/service.py`：会话重置有独立 `history_after_journal_id`；当前请求通过有界 QQ Journal 增量构建。
- `astrbot-plugins/v2_dsh_router/mcp_server.py`：现有 `history_*` 工具使用可信当轮范围，读取下界不能因为新增记忆而被取消。
- `dsh/plugins/agent-profile/decision-guide.mjs`：已有具名 `systemPrompt.section` 装配机制；可参考其分层方式，但**具体如何把宿主可信记忆送入独立 DSH 进程仍需核实**。
- `dsh/templates/group/AGENTS.md`：当前 `memory/` 为群成员手工资料约定，不是已经存在的自动 Memory 子系统。
- `dsh/plugins/agent-profile/persona.mjs`：群 Agent 的有效人格来自群工作区 `persona.md`，在每轮 prompt 装配时读取；基于 Session ID 的可选全局 Persona 不应被错误用于群记忆分片。
- `dsh/plugins/agent-profile/group-app.mjs`、`group_app_runner.py`：既有群应用操作及每应用 `data/` 的隔离执行机制可供评估，但**现有接口尚未直接证明可由宿主后台安全地读写和维护自动记忆**。
- `dsh/plugins/agent-profile/group-write-policy.mjs`：群工作区存在 Owner/授权编辑者的写权限；因此把数据存入工作区不能等同于“普通有权写工作区的人无法改动数据”。
- `dsh/plugins/agent-profile/group-sandbox.mjs`：工具名称采用显式允许列表；新增 MCP 记忆查询须同步审查它及子 Agent 的最小授权边界。

## 8. 明确不要求一期实现

不要求记忆每句话、不要求永久保留所有模型中间步骤、不要求复杂推理链、Embedding 向量库、记忆衰减评分、跨群共享人格或画像、自动扩展无限 Prompt，也不要求按 Persona 各建一份记忆库。记忆归群工作区所有，不等于必须以散乱、可随意编辑的文本文件来实现。

本阶段交付应是**小而可靠的持久背景 + 可核对经历 + 可纠正遗忘**。后续仅在发现具体体验或性能瓶颈时再讨论升级。
