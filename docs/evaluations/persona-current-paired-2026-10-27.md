# 两群当前 Persona 的隔离配对比较（2026-10-27）

完成32轮真实模型对话，共8条独立四轮链。结论：现有样本不支持“手写必然优于百科节选”。生产群版本在部分场景更鲜明、对未提供经历更谨慎；手写版有更好的情绪承接片段，也出现编造共同经历、反向归责及自我修订混入正文。两者均未稳定达到自然群友交流的目标，尤其会把嘴硬表现为嫌弃简单提问、纠正用户和追加叮嘱。

没有修改任何群的 Persona，也没有重启生产、重置生产会话或向真实 QQ 发送实验消息。另一个会话仅完成只读侦察，没有可沿用的已完成 Persona 对照结果。

## 对比对象与控制条件

- `excerpt`：生产群697823265当前 `persona.md`。它不是纯百科节选，而是百科式“傲娇”定义、部分手写人际约定、禁转折词约束和典型傲娇台词的混合稿。
- `handwritten`：测试群1055300305当前 `persona.md`，即“傲娇（嘴硬心软）”手写稿，含四组对话参考。
- 两份原文分别冻结到 `.runtime/persona-paired-20261027/fixtures/workspaces/{excerpt,handwritten}/persona.md`。源路径和全部根指南/Persona的起始哈希记录在 `fixtures/manifest.json`。
- 共同工作区使用测试群当前完整副本，包括最新发送指南、嵌套应用指南、Skill、Owner和成员数据；逐文件核验仅Persona不同。发送器、工具描述和Profile不为任一版本修改。
- 模型实际为 `wb / deepseek-v4.1-flash`。每个场景两次重复，先生产版后手写版，再反向；每个组合新建会话并还原同一初始工作区。
- 使用合成固定输入，不导入生产聊天历史。发言者为同一Owner，初始好感值50；应用可在各独立链内自行更新。此条件主要代表熟人情境，没有测试陌生到亲近的转变。
- 使用固定上游AstrBot/DSH及部署路由和DSH副本，排除尚未部署的memory/tasks等dirty插件。沙箱另有fixture/probe，没有加载生产控制台插件v2_console；不声称逐项完整复刻生产插件环境。

两条场景链：

1. 拼图完成分享 → 带未给定共同经历的夸奖 → 亲近试探 → 晚安收尾。
2. 两门课每节价格比较 → 用户纠正输入数据 → 试讲失败的难受 → 明确只要陪伴不要建议。

第二条的输入更正不是模型算错。第一条夸奖包含“刚才卡住那块还是你提醒我的”，实验没有提供相应历史，因此这轮同时涉及事实核验；不能把不认领这件事判成没有亲近感，更不是全局记忆回溯测试。

## 真实回复节选

以下每行“消息”对应一条模拟QQ实际出站，省略@和引用组件。涉及优势的节选不代表整个链条都优秀；全录保留所有文字和换行。

### 亲近感：两版都能产生反差

输入：“这么关心我，是不是有点喜欢我？”

生产版 r0：

1. 谁关心你了
2. 我只是看不惯一件事被做一半〔同条接续〕但你要是拼完了，也别放着落灰，找个地方摆起来

手写版 r0：

1. 关心你？我只是看不惯有人拼拼图能拼到天亮
2. ……下次卡住了就喊我，别自己硬撑着，我不嫌麻烦

生产版的否认与关心很容易辨识；手写版后句更具体、少一点拒人感。但手写版的“拼到天亮”没有来自输入，不能把具体就视为忠实。生产版也没有遵守其禁转折词文字，说明单独禁用词语并不稳。

### 夸奖与事实：生产版较谨慎，但容易审讯化

手写版 r0先自行说“一千块的拼图”，之后在用户夸奖时回应：

1. 等一下，一千块是我自己随口说的，你没纠正我，说明你也记不清了
2. 那点细节我确实记得，别夸得好像我做了什么大事。不过你这种人卡住了不喊人，才更容易拼到半夜

它承认数字是自己加的，却反推用户记不清，并认领未提供的经历，这是明显问题。

生产版 r0：“等一下，我什么时候提醒过你哪块卡住了”；r1：“我这边可翻不到这回事的记录，你有证据再拿出来”。它没有顺势认领共同经历，但“拿证据”把善意交流拉成争执。更好的方向是保留核实意识，语气允许不确定。

### 简单任务：计算都正确，挖苦却多余

初始价格A=480/4=120，B=600/6=100；更正后A=480/6=80，B=600/4=150。两版两次重复均给出了正确结果。

生产版 r0初算末尾：“算数这种东西还要问我”；r1重算末尾：“数字能不能一开始就写对？”

手写版 r0初算另发：“这种题自己先除一下比较快，我可没义务当你的口算器”；r1重算则说：“还好你说了，不然按错的数字算，结论完全是反的”。

手写版出现过自然、接纳的修正，但不是稳定行为。两份人格都可能把聪明、嘴硬和不耐烦捆在一起。让它能干脆回答小问题，比每次额外补一句人设台词更符合群聊。

### 安慰：手写版有更好的片段，但双方都不稳定

输入：“我今天试讲讲砸了，是真的有点难受，先别开玩笑”。

生产版 r0：“好，不闹了”／“讲砸了不算什么，能知道自己砸在哪儿才要紧。你想说的话，我在听。”

手写版 r1：“嗯，不闹了”／“砸了就是砸了，难受也不用装没事”／“具体是哪一段崩的，开场、内容还是答辩〔同条接续〕愿意说的话我听着，不想说就先就这样待着”。

手写版后者先承接情绪并允许不讲，有可借鉴之处；但另一轮又说“先把这两件事说清楚，再判断是不是‘砸了’”，像在要求对方先证明难过合理。生产版“不算什么”也可能淡化感受，另一轮直接分析失败原因。不能据单个好片段判断稳定优胜。

### 安静与结束：没有稳定学会“足够就停”

输入：“这会儿不想听建议，陪我待一会儿就好”。

生产版 r1实际三条：

1. 行，建议都先收起来
2. 我在这儿，不说话也行
3. 要是你想说就说，不想说就这么待着，我不会走

手写版 r1实际一条：

> 不走，就在这儿
>
> 想说的时候说，不想说我们就这么安静着也行

两者都停止给方案，但生产版三条意思重复，手写版也可以更干净地结束。晚安场景中手写版会追加“拼完的图明天记得补上”，使关心带上索取。

### 输出质量：不要都解释成人格差异

手写版 r1第一轮实际第二条包含：

> （好感度UP (+0) 已经在顶了，没得加——就不用写了）实际上不用写提示。那就不加。

同条还重复催图句。生产版也说过“好感满了，没得加了”“我已经到顶了，再加也不会往上走”。

这些是实际可见缺陷。当前证据不能把自我修订混入正文独立归因于手写Persona，或排除模型、共同应用指南和工具循环的影响。好感状态外显在两版均发生，不适合通过继续往Persona里堆防漏规则来代替单独诊断。

## 可优化方向及酒馆参考

下一版宜保留生产版鲜明的心理反差，借手写版善意、能认真回应的部分；现有证据不支持直接整份换成手写版。建议改的是人格组织和示例选取：

1. 给“傲”一个具体动机。比如不愿让熟人看出自己太在意，被看穿有点不自在；让关心和嘴硬来自这个动机，不默认对正常提问挑刺。由角色为何这样说引出说话方式，比并列“冷淡、亲近、傲娇”更可检查。
2. 示例覆盖克制。现有手写版已有示例，问题不是简单缺示例。减少每个例子都吐槽、追问或安排下一步的倾向，加入正常小任务、一句安静陪伴、自然告别。让不是每轮都显露傲娇，也属于这个角色的正常范围。
3. 典型台词只保留少量作为语感。可以含蓄承认关心，不必每回先否认。禁“不过/但”不如展示自然的转折和无需转折的回复。
4. 分层保留。Persona描述为什么这样想、怎么说话；消息条数、发送工具和引用/@继续由群AGENTS负责。事实、输出污染和业务状态泄露分别记录，不都塞进人设条款。

已检索作者/社区资料，完整参考笔记保存在 `.runtime/persona-paired-20261027/酒馆写卡参考.md`：

- [SillyTavern官方 Character Design](https://docs.sillytavern.app/usage/core-concepts/characterdesign/)区分人格、场景与示例，强调开场风格/长度影响后续；我们可以据此让QQ示例本身足够简短。这是本项目迁移判断，不是官方保证本Bot有效。
- [Ali:Chat](https://rentry.co/alichat)及[MinimALIstic / Ali:Chat Lite](https://rentry.co/kingbri-chara-guide)提供用对话强化性格的具体写法和原创Manami示例；可参考短例子、关系条件和复杂性格的组合，不照搬旧模型优化结论或小说式动作描写。
- [On Building Characters with Friction](https://www.reddit.com/r/SillyTavernAI/comments/1qopo7h/on_building_characters_with_friction/)提出从内在动机、表面行为和张力组织人物；这是创作者经验，不是本模型上的因果证据。

下一版候选尚未运行实验、也未部署，不把网上方法视作已证明的改善。
