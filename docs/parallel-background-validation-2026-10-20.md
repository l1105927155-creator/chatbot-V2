# 并行研究与前台忙碌回执（2026-10-20）

此前 Owner 私聊长检查没有调用后台工具，父轮次持续占用同一会话锁；进度询问排队约 13 分钟。固定版 DSH 已有并行子 Agent，集成层却限制同一父会话只能启动一个研究任务。因此，同时处理多个研究与避免排队时完全无回应需要分别解决。

## 本轮变更

- `dsh/plugins/agent-profile/background-research.mjs`：每父会话最多 3 项研究，进程级仍最多 3 项。按父会话串行创建、绑定子 Agent，绑定完成立即释放创建锁，研究结果并行等待。保留独立任务编号、请求者、权限、取消和结果通知。
- `astrbot-plugins/v2_dsh_router/service.py`：父轮次仍运行时，新唤醒消息可先获得程序发送的忙碌回执，再保持原有 FIFO 排队。回执走 AstrBot，群聊原生 @ 新消息发送者；不调用模型，不推进 Journal 消费游标，不占用最终回复的提及设置。已消费消息重投不发回执。单次回执最多等待 5 秒，失败不丢弃原请求，不自动重试不确定发送。
- Profile、常驻决策入口及 `background-research` Skill：区分 Shell 前台限制与原生后台子 Agent；耗时操作先告知，适合独立完成的多步研究先加载 Skill，启动后简短确认并结束当前轮次，让前台接收新消息。支持按任务编号分别查询、补充和取消。

Owner 研究子级仍仅能读取文件和查询网页；群子级沿用当前群沙箱，普通私聊仅有其现有研究工具。本轮没有开放通用后台写入/编码代理，也没有修改上游 core。

## 边界

并行研究启动并结束父轮次后，前台可以继续由模型交流。如果主模型仍选择长时间留在前台，程序回执只能及时确认收件，后续实质回复仍需等待；它不会伪称任务已经转入后台。原生进程内子任务不承诺重启后续跑。真实 QQ 客户端体验仍需部署后观察。
